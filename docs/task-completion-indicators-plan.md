# 任务列表反馈与处置完成标识规划

关联事项：PI-20261109-007；延续 PI-20261109-003、PI-20261109-005。用户在初版实现后进一步要求简化，以下“最新口径”覆盖原双维度展示方案。原方案保留供追溯，实际检查与部署状态以台账最新追加为准。

## 最新口径：按发现反馈识别已处理

任务列表恢复“发现 / 价值反馈”，只保留待反馈、反馈中及反馈完成标签，移除独立问题处置标签及数量。详情选择有帮助、误报或忽略后显示“已处理”，撤销后显示“待处理”；“处理状态”筛选与旧 open 直达地址均按有无当前三类反馈判断。历史修复反馈继续按未评价处理。

跟进问题入口只显示编号；代码修复及跨任务跟进记录继续在跟进问题页面管理，不由发现反馈自动改写。部分覆盖、无有效结论、无发现、未知反馈及有效版本变化等保护沿用。初审与有效补审通过共享 FindingsPanel 使用同一展示和筛选规则。以下第 1—6 节是此前方案，不能据此恢复已移除的处置标签。

## 1. 目标与展示层级

用户应直接看出当前任务的发现是否已反馈、关联问题是否已处理，无须加总三类反馈或进入详情计算。保留现有灰白蓝视觉及 Ant Design，局部增强任务列表的“发现 / 价值反馈”区域，不扩大为整页重设计。

建议列名调整为“发现 / 反馈与处置”，单元格按三层显示：

1. 发现数量与最高级别，沿用现有内容。
2. 两个带文字的 Ant Design Tag：反馈进度、问题处置进度。待办用橙色、进行中用蓝色、完成用绿色、未知或无需操作用中性色，不能只靠颜色表达。
3. 保留“有帮助 / 误报 / 忽略”明细，次要灰字呈现。

列表不增加“全部完成”按钮，两个标识随已保存的反馈和问题状态更新。整行进入详情的行为保留；手机端两个标识可自然换行。

## 2. 反馈进度

使用当前有效发现的 `feedback_summary`，分母为 `total`，剩余为 `unmarked`，已反馈为 `total - unmarked`。展示前校验计数完整、非负且各类别加未评价等于总数；缺失或不一致显示待核实，不以零补齐。

| 条件 | 展示 |
| --- | --- |
| 有发现，全部未评价 | 待反馈 · 剩 N 条 |
| 有发现，部分已评价 | 反馈中 X/N · 剩 Y 条 |
| 有发现，全部已评价 | 反馈完成 N/N |
| 已确认当前结论没有发现 | 无需反馈 |
| 反馈投影缺失或计数不可信 | 反馈待核实 |

“有帮助 / 误报 / 忽略”均表示已经做出反馈；历史“已修复”反馈仍按未评价处理。这里的反馈完成表示每条已有选择，不改变首页“有效评价占比”中忽略不算有效评价的统计规则。撤销反馈后立即回到未完成状态。

## 3. 问题处置进度

使用 `issue_summary` 中按最终问题身份去重的持久化计数。已处理数为 `fixed_count + ignored_count + false_positive_count`，待处理数为 `open_count`；不使用反馈条数反推。必须明确是“个问题”，与“条发现”区分。

| 条件 | 展示 |
| --- | --- |
| 关联问题均已知，全部开放 | 待处理 N 个问题 |
| 关联问题均已知，部分关闭 | 处理中 · 剩 N 个问题 |
| 有发现且关联问题均已知，无开放问题 | 已处理 N/N 个问题 |
| 已确认当前结论没有发现 | 无需处理 |
| 关联缺失、合并链异常或投影不可用 | 处置待核实；如有已知开放问题，可附“已知待处理 N 个” |

“已处理”包括人工标记已修复、已忽略和误报；提示中可展示构成，详细历史仍在问题详情。人工标记不代表系统已验证修复。`issue_summary.complete` 仅表示问题关联信息完整，不能直接当作处置完成；还必须确认存在发现、未知数为零且开放数为零。

## 4. 范围与更新边界

- 部分覆盖、排除或豁免仍保留现有提示，并说明“仅当前已发现范围”；即使两项完成，也不能显示整次评审全部完成或代码没有问题。
- 排队中、评审中、未形成有效结论时保留对应状态，不因计数为零显示无需操作。完整且无发现时保留“本次未发现问题”；部分覆盖但当前无发现时显示“当前范围暂无发现”及覆盖提示。
- 两个维度互不阻塞：允许“反馈完成、仍待处理”，也允许“未反馈、问题已处理”。不增加与事实可能冲突的手动任务完成开关。
- 初审、补审、重新评审均沿用服务端当前有效版本；新发现、反馈撤销、问题重新打开后，状态可退回待办。合并问题按最终身份去重，反馈仍按发现逐条统计。
- 第一阶段复用已有两个只读汇总，无需新增写接口、schema 或 Worker 流程。若增加筛选，作为后续阶段在服务端分页前筛选，不能只过滤当前页；明确分为反馈进度、处置进度两个筛选维度。
