## 2. 范围预检与预算

`range_preflight.py` 读取入队的固定 base/head；无显式 base 的单提交取第一父，根提交对比空树。禁用外部 diff、textconv、hooks、fsmonitor、全局 Git 配置与替换对象。不执行被评审仓库的脚本或过滤器。

仅同模式普通文件修改可以参与换行判定：将 `CRLF` 转为 `LF` 后做精确字节比较，不忽略缩进、其他空格、末尾换行、编码或逻辑变化。新增、删除、重命名、权限或类型改变、符号链接、子模块、NUL 二进制及非 UTF-8 内容不据此免审。混合逻辑修改仍完整纳入 OCR。

新快照的 `input_policy` 固定以下边界，不新增可随意改写生产的 UI 开关：

| 项目 | 上限或行为 |
| --- | --- |
| 模式 | `analyze_only`，`filter_enabled=false`，策略排除数为 0 |
| 分析文件数 | 最多处理 5,000 个路径 |
| 单个 blob / 累计正文读取 | 1 MiB / 32 MiB |
| 原始路径输出 | 最多 2 MiB |
| 预检 | 10 秒；超时、读取失败或超限标记受限/不可用，未确认文件仍纳入 |
| 配置命令 | 所有配置命令合计最多 30 秒 |
| 范围预览 | 最多 60 秒，工件超过 16 MiB 拒绝校验 |
| OCR 总预算 | 配置、预览、正式评审共用项目原有预算；短上限不额外增加总预算 |

Git 准备继续沿用现有有界命令与重试，不计入 OCR 总预算。新记录通过阶段起止区分 Git、预检、配置、预览、范围校验、正式评审及结果校验；预算耗尽仍不整批自动重跑。

预览验证路径、选中布尔标记、重复路径及实际选中数量，防止损坏的零计数导致错误跳过。`max_files` 仍是实际 OCR 候选范围上限，不是“前 N 个”：201 个候选遇到 200 上限时，正式模型调用前以 `scope_limit` 失败。合并后任务会在此之前保存 OCR 候选和规则排除计数；合并前也保存范围预检，但失败前的候选计数尚未单独持久化。

预检保存为 `scope-analysis.json`（权限 `0600`）并存 SQLite，内容仅范围、路径和计数，不含正文。列表省略逐文件换行路径；详情可查看。原始 Git 计数与 OCR 选中数分别展示，不能混作同一口径。

### OCR 排除兼容性实测

本地固定 OCR `1.12.9 (bccbc15)`，临时合成仓库、隔离 HOME，所有命令仅 `--preview`，未配置或调用模型：

| `--exclude` 输入 | 合成预览事实 |
| --- | --- |
| 不传 | 五个合成路径均选中 |
| `/a.py` | 没有排除 `a.py` |
| `a.py` | 排除对应简单路径 |
| `dir/a.py` | 排除对应目录路径 |
| `/space name.py` | 没有排除 `space name.py` |

不能由此推断 OCR 所有排除参数无效。任意路径的可靠编码（包括逗号、glob 特殊字符等）、冻结策略与正式 manifest 一致性尚未验证，因此本轮按方案降级：**只分析和拦截规模，不自动过滤、不因纯换行自动跳过**。全部换行文件仍可能进入模型；只有 OCR 原有规则排除或空差异才会跳过。

可重复探针命令（仅使用本地已安装 CLI，不下载）：

```sh
.venv/bin/python -m ocr_manager.ocr_filter_probe --command .local-tools/node_modules/.bin/ocr
```

后续开启过滤必须重新验收任意路径、同一策略预览/正式集合一致性及 manifest，不能直接加未经验证的参数。`max_files=200` 仍只是试点建议，未修改任何生产项目；有限 Token 值需用代表性成功任务校准，并说明并发在途请求可能造成预算超额。

## 3. 时间、原因和成本口径

| 字段 | 实际含义 |
| --- | --- |
| 首次排队 | 创建至第一次尝试开始；从未启动且排队中则计算当前等待 |
| 本次 / 最后执行 | 当前尝试开始至计算时刻，或最后一次已结束尝试的耗时 |
| 累计执行 | 各次已结束尝试相加，运行中再加当前尝试，不包含排队和退避 |
| 重试退避 | 已保存的尝试结束至最早重试就绪时间；仍退避中只计已经过部分 |
| 就绪后等待 | 最早就绪至实际领取或当前时间，不与退避重叠 |
| 总历时 | 创建至最终结束或当前时间，包含全部等待与尝试 |

时间按 UTC、同一读取快照计算。旧记录缺字段、编号不完整或负区间不补造，显示未知或历史不完整；不会用总历时冒充执行。Worker 重启恢复写入的结束时间只代表恢复记录时刻，无法知道真实进程何时停止，该次执行及阶段耗时不当作精确值累计。

稳定原因区分空差异、OCR 规则排除、规模超限、预算耗尽、模型 HTTP 故障、部分覆盖、取消和中断。失败、跳过、取消不以“0 条发现”暗示通过；纯换行未启用过滤，不能归因为“纯换行已跳过”。HTTP 摘要仅使用可信状态码，不暴露上游原始响应。

累计用量逐次读取安全投影；有总 Token 但缺输入/输出时保留已知下限，标记不完整。每次费用按该次历史单价，不用当前模型价格回算；不同币种分列。无可信最终结果、无单价或异常价格时不填零费用。超时不等于未计费。历史报告只使用指定尝试的状态、范围、时间及费用，不沿用当前任务累计或取消状态。

近七天按项目、当前状态和原始 Git 文件规模（0–50、51–200、201+、未知）分组。成功执行 P50/P95 仅取 `complete` 且时间完整任务的累计执行；排队分位数只用已启动且首次时间已知样本。跳过不进入成功执行分位数。超时占比以本组任务数为分母；重试次数为尝试数减一，包含人工重评审，不等同于自动重试次数。Token 为已知下限，同时披露未知用量任务数。

分位数用最近秩法并展示样本数，小样本不代表稳定线上 P95。原有平均耗时改为仅成功任务末次平均执行，不能与累计执行分位数混用。列表批量查询尝试而不是逐行查询或读取工件；指标按 500 个任务分块读取安全用量/价格投影。

## 4. 数据库与发布约束

数据库 `35 → 36` 增加任务范围、原因、领取就绪时间，尝试范围、原因、调度/重试就绪时间，以及 `review_stage_timings`。触发器在尝试写入时冻结对应证据，退出运行时关闭未结束阶段。旧字段保持 `NULL`，不倒推或批量回填历史。

新 `review_policy` 为版本 2，仍最多两次完整尝试、不重试整体超时；`input_policy` 版本 1 进入合并后快照哈希及合并前 `execution_policy`。恢复识别 `review_policy` 版本 1、2 的两次预算，更早无策略保留原三次恢复上限；这不允许旧快照绕过配置冲突继续运行。

从 34 升级会依次执行 35、36。上线前必须在副本演练，成对备份数据库及私有主密钥，处理在途与旧队列，待 OCR 空闲协调升级 API、Worker、monitor。旧快照包含第一阶段已排队任务，不能静默升级；应按新配置人工重新评审，保留原历史。回退必须停止相关进程，在新目录恢复升级前配对备份并处理上线后新增记录补偿；不得降低 `user_version` 或让旧版打开高版本活库。
