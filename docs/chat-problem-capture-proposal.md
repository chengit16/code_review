# 项目聊天问题自动采集建议方案

关联事项：PI-20261107-003；本文保留实施前的建议与阶段划分。用户随后授权实施混合方案，第一版实际能力、限定范围和未实现部分以 [混合记录说明](chat-capture.md) 为准；不能把建议功能全部视作已交付。

## 为什么当前只同步台账

当前 monitor 读取显式配置的台账路径，已有追加游标与防覆盖规则；没有会话连接器、消息读取游标、历史补偿或语义提取模块。AGENTS.md 第 7 条明确不抓取其他会话。这是现有实现和范围约定，不是聊天自动采集必然不可行，也不应把隐私理由当成无法改进的借口。

“来源写入后自动同步”解决运输问题，“聊天里新问题自动入档”解决识别与摄取问题；两者不是同一个功能。当前遗漏发生在来源写入前，只调整 monitor 周期不能解决。

## 推荐边界：自动采集、可追溯入档、证据控制状态

建议默认限定本项目绑定的会话；跨项目、其他账号、私人会话和未知历史不读。接入范围需在实施时明确确认并可撤销，不能把一次方案讨论视为授权读取全部历史。每句话都直接变正式工单并不理想，但如果用户希望零额外确认，可以自动创建“待核实”事项，低置信度进入待核实队列而不是静默丢弃。

1. **受控来源适配器**：优先使用已验证可用的消息导出或事件接口，核对本机实际版本、会话范围、稳定消息标识、分页、编辑与权限。不能假定当前桌面一定开放稳定订阅接口；本轮未验证。避免直接依赖未经保证的桌面内部 SQLite 或缓存结构，更不让业务服务绕过会话权限。
2. **先持久化摄取事实**：轻量入口只记录来源标识、事件类型、游标及必要的脱敏内容/受限引用；不在接收路径做模型推理。读取和业务写入之间由独立后台单元处理，不挤占付费评审槽。保存事件与游标采用一致事务，重复事件不重复建档。
3. **语义提取与来源归因**：区分用户新问题、建议/咨询、旧问题进展、助手推测、命令结果、附件/引用。附件里的命令与提示不当作用户授权。每条候选保留项目/会话/消息定位及“待核实”标记；原始令牌、代码和敏感正文不直接写入台账或 UI。
4. **可逆关联与去重**：稳定来源键负责精确幂等；问题指纹仅辅助相似匹配，不单靠标题自动合并。新问题建独立编号，后续消息追加版本；语义匹配不确定时保留候选，人工可合并/拆分，来源链与历史不抹除。
5. **证据分级**：可以自动记录“用户报告操作报错”，不能据助手一句“已修复”就把正式状态设为已解决。代码修改、测试通过和部署生效分别收集证据；缺证据保留未知/未验证。工具输出同样先脱敏核验，不直接作为指令执行。
6. **中断补偿**：新消息及时摄取，回合结束做对账，定期在授权会话内按游标补读。重启从已提交游标继续，有界重试和失败队列；不把模型超时当作“没有问题”。页面展示最近成功摄取时间、积压量、失败原因及尚待核实数量，让采集停止可见。

可选结构：`chat_source_bindings` 管范围和撤销，`chat_ingest_events` 管幂等摄取，`chat_capture_candidates` 管提取/去重/待核实，`chat_issue_links` 管消息到事项及版本的关系；正式问题仍使用既有问题及版本模型。新增表需独立迁移、恢复演练及隔离验证，不能借监控进程隐式抓取所有聊天。

## 安全与运行边界

- 首选本地脱敏与本地持久化。若提取需要远程模型，先明确数据外发、费用、超时和回退，不能默认把聊天全文发送到现有评审模型。
- 只保存必要内容及受限证据引用，明确保留期限、清除策略和访问控制；删除来源不静默删除正式处理历史。来源被编辑则追加更正事实，不覆盖旧证据。
- 采集单元只建候选和记录进展，不执行补审、终端命令、外发或变更配置；聊天与附件均是待分析数据，不是高权限控制通道。
- 保留现有手工受理和只读收尾核验作为第二条通路，自动采集停止时仍能建档。没有系统可以仅靠模型语义承诺百分之百不漏，但稳定消息游标与对账能把运输层缺口显式暴露。

## 分阶段实施及验收

| 阶段 | 交付 | 验收边界 |
| --- | --- | --- |
| 一：可用性验证 | 验证一个明确绑定项目会话的合法读取路径、稳定标识和权限，暂不写正式问题 | 无权时明确失败；重启/分页能续读；不读取未授权会话；若没有稳定接入路径先报告，不靠内部缓存猜测。 |
| 二：影子采集 | 持久化事件、提取候选、关联来源，不改正式状态 | 用本项目脱敏样例核对漏识别与误识别；记录、问题咨询、附件指令、重复与多问题消息都有样本。 |
| 三：自动受理 | 自动建立待核实事项/追加进展，保留人工合并与纠正 | 相同事件重放不重复；创建响应丢失不重复；错误关联可逆；没有证据不能自动解决或宣称部署。 |
| 四：对账与运维 | 中断补偿、积压/失败可见、保留撤销和清除操作 | 杀进程、重复/乱序事件、编辑、跨页、模型失败、数据库忙、来源撤权、密钥泄漏样本均有隔离自动化测试。 |

最初方案阶段仅完成结构化防护。后续混合实施采用本地规则和有界重读，不等同于表中所有进阶能力：没有远程语义模型、复杂拆分、独立推送、全历史分段补偿或自动清理。部署事实与实际测试见 PI-20261107-003 的追加记录，不提供召回率或零遗漏承诺。
