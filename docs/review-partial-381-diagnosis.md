## 3. 补审按钮为何禁用

本轮调用任务 #381 的只读资格接口，返回 `eligible=false`、`reason_code=feature_disabled`。现有私有配置未显式设置补审开关和仓库白名单，使用默认关闭值。目标内部仓库 ID 为 2，这不是 GitLab 项目 ID。

解除该阻塞需要管理员在原私有配置中合并以下字符串键值，保留其他配置和原主密钥，再协调相关进程读取一致配置：

```json
{
  "OCR_APP_REVIEW_RECOVERY_ENABLED": "1",
  "OCR_APP_REVIEW_RECOVERY_REPOSITORY_IDS": "2",
  "OCR_APP_REVIEW_RECOVERY_MAX_BATCHES": "1",
  "OCR_APP_REVIEW_RECOVERY_MAX_TOTAL_TOKENS": "100000"
}
```

本轮未修改这些配置。开启开关不等于该任务必然合格；之后还会检查来源、当前配置摘要、活动批次、范围和预算。特别是历史任务可能存在配置漂移，不能通过关闭校验强行补审。Token 上限不是金额上限，真实试用仍需明确费用边界；人工确认并提交之前不得代为创建批次。
