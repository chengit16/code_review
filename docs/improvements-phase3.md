# 问题与改进第三阶段：复盘汇总与统计

实施日期：2026-11-06。增加管理员专用、只读的“复盘汇总”视图，将当前累计、日期窗口活动与待跟进清单分开。源码实现不代表业务实例已部署；本轮不访问业务服务或业务数据库。

## 1. 页面入口与范围

从“运维与审计 → 问题与改进 → 复盘汇总”进入，地址为 `/improvements?view=summary`。筛选键为 `summary_start_date`、`summary_end_date`、`summary_category`，不会读取问题记录或优化历程视图的其他筛选条件。

- 当前累计：台账记录数、未解决数、已解决占比、显式关联主题的记录数、优化主题数与阶段数。
- 独立分布：台账进展、类型、分类、代码修改、本地验证和部署生效；主题进展与分类；阶段进展、代码、本地验证和部署。
- 窗口内活动：按自然日统计新增记录、记录追加进展、新增主题和主题追加进展。提供柱图及可展开逐日表格。
- 当前清单：未解决记录、验证待跟进、部署待确认、未完成主题。按最久未更新优先显示前十条，包含完整总数；各组可重叠，不能相加当作独立问题数。
- 明细导航：台账与主题进展、分类及台账类型可以跳到相应列表；待办可以直接进入详情查看证据与追加进展。

## 2. 统计口径

| 指标 | 分母与规则 |
| --- | --- |
| 当前累计 | 当前分类下全部持久化记录或主题，与活动日期无关，不是按日期回放历史状态。 |
| 未解决记录 | 台账状态不为 `resolved`，包括暂缓；同时包括问题记录和阶段改进。 |
| 已解决占比 | 当前 `resolved` 台账数 / 当前台账总数；零分母显示“—”，不是本期解决率。 |
| 关联覆盖 | 台账存在至少一条主题关系，按台账编号去重；关联主题可属于其他分类，不因多主题关联乘倍。 |
| 阶段累计 | 按所属主题的当前分类筛选，阶段是分母，不是主题数量。 |
| 验证待跟进 | 本地验证失败、受阻，或代码已修改但本地验证未运行。 |
| 部署待确认 | 仅本地验证通过且部署为未部署或无法确认；排除部署不适用。已解决也可以出现在此清单。 |
| 未完成主题 | 当前主题不为 `completed`，包含暂停、暂缓；主题完成不推断部署完成。 |
| 新增活动 | 实体 `created_at` 落在日期窗口内。历史快照不是新实体。 |
| 追加进展 | 对应历史表版本大于 1，且历史 `created_at` 在窗口内；同一事项多次保存按次数累计，不等于多次解决。初始快照、创建重放、失败与冲突不计入。 |
| 活动分类 | 按实体当前分类统计，不按当时历史快照的分类回放。重新分类后其历史活动也归入当前分类。 |

默认活动窗口为最近 30 个北京时间自然日，含今天。只填结束日期时，从该日向前取 30 天；只填开始日期时，截至今天。最多 366 天；反向、过长、早于 1970-01-01 或晚于北京时间今天的日期拒绝为 422。首尾日期均包含，服务内部转换为带时区 UTC 半开区间，分桶使用同一 `Asia/Shanghai` 时区规则，包含历史夏令时处理。无活动日补零。

不计算平均解决时长、复发率、历史时点状态或生产成功率：当前模型没有足够明确的复发关联及生产验收事实，不能用编辑时间或保存次数代替这些指标。手工记录的“验证通过”“部署已生效”仍只是持久化声明，不表示统计接口实际执行检查。

## 3. 数据、接口与权限

`GET /api/improvement-summary` 接收可选的 `start_date`、`end_date`、`category`，返回口径明确的响应模型及读取时间。所有查询共用同一 SQLite 读事务，避免并发保存使总数、分组和待办不一致；独立聚合台账、主题、阶段及历史活动，避免一对多关联扩张总数。返回内容不包含正文、证据长文本、操作者、凭据或 OCR 工件。

复盘使用第 39/40 版现有表，不新增迁移，不将汇总结果另存成报告快照，也不创建或修改台账、阶段和历史。接口要求管理员，只读账号不能直接访问；刷新和重试均为查询，不触发 Worker 或任何外部调用。

前端查询键包含筛选，使用取消信号隔离旧请求；记录和主题成功保存后使复盘缓存失效。查询或刷新失败明确显示恢复入口，不继续把旧结果展示为最新，也不将失败当作零样本。长窗口图表与逐日表格只在自身区域滚动。
