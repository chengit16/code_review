# Ant Design 组件迁移影响评估

## 评估边界与结论

2026-11-07，根据当前源码进行静态评估，对应 PI-20261107-007。本轮不安装依赖、不实施原型、不修改业务代码、不发布运行实例；本文不是已经批准的迁移规划或排期。

**全量替换属于中到偏大的前端重构，不是一次换肤，也不等于全栈重写。** 可以保留 React、Vite、React Router、TanStack Query、API 契约和后端数据模型。工作量主要在控件契约适配、表单与确认流程、表格移动端、CSS 收敛和自动化回归。若目标仅是与参考图颜色一致，PI-20261107-006 已完成，无须为配色额外引入组件库。

## 替换范围及风险分层

| 层级 | 候选替代 | 风险与约束 |
| --- | --- | --- |
| 基础展示 | `Button`、`Tag`、`Alert`、`Empty`、`Spin`、`Card`、`Tooltip` | 相对较低；保留可访问名称、危险提示、状态语义，不把加载失败渲染为空列表。 |
| 基础输入 | `Input`、`Input.Password`、`Input.TextArea`、`InputNumber`、`Checkbox`、`Switch`、`Select` | 中等；回调和值类型不同，空值/零值/未设置/禁用不能合并。`InputNumber` 清空可能返回空值，不能悄悄转成有效预算。 |
| 容器与导航 | `Layout`、`Menu`、`Tabs`、`Collapse`、`Modal`、`Drawer`、`Pagination` | 中到高；保留路由和 URL 所有权、加载时机、草稿生命周期、键盘与弹层行为。 |
| 数据列表 | `Table`、`List`，配合自定义列与移动端内容 | 高；不是替换标签即可完成，需显式控制服务端分页、筛选与当前页选择。 |
| 复杂表单 | 可采用 Ant Design 输入控件；是否全面使用 `Form` 另作决策 | 高；不要在同轮额外重写所有表单状态与校验体系。 |
| 确认流程 | 上下文内的确认弹窗或 `Popconfirm` | 高；原生同步确认改为组件异步交互，需重新核对操作触发点与并发锁。 |

## 六个关键影响面

### 1. 表单与草稿是最大风险之一

目前 `useConfigurationDraft` 保留编辑基线，后台刷新不覆盖草稿；仓库编辑不同页签可各有草稿，部分保存后不丢弃其他页签。Ant Design 的表单初值、保留字段和弹窗卸载策略必须与此对齐，不能简单把查询数据持续同步进表单。

重点保护：保存冲突保留草稿、查询失败不能保存默认配置、密钥不进浏览器持久化、规则切换可取消、预算为空不能自动批准。原生 `required`、`min`、`max`、`onSubmit` 与 Ant Design `Form` 的校验/完成回调不是同一契约。按钮还须区分组件视觉 `type` 和表单提交的 `htmlType`，防止回车或取消按钮误提交。

### 2. 同步确认改异步，会触及真实控制流

`confirmDiscard` 当前直接返回布尔值；路由拦截依据结果决定继续或取消。退出时使用可取消的同步事件，也依赖即时判定。改成 Ant Design 确认框需要显式处理等待、确认、取消与请求进行中，而不是把 `window.confirm` 原地替换成一个函数名。

删除、恢复配置、重审、调整额度、补审排队、通知重发必须维持各自独立命令。确认前不得发请求，重复确认不得重复提交，原幂等键在网络响应丢失时继续复用。浏览器刷新/关闭的 `beforeunload` 提示受浏览器限制，不能承诺用自定义 Ant Design 弹窗完全替代。

### 3. 表格与分页要保持服务端和当前页边界

任务列表以 URL 作为筛选和分页事实，URL 变化会重建勾选范围；可重审项目还受任务状态与活动补审约束。Ant Design `Table` 的 `rowSelection`、分页、排序、筛选必须是受控的，不让组件自行对当前页数据假装完成全量搜索，也不能默认保留跨页选择改变操作范围。

现有小屏不是只横向滚动：任务行会收敛为摘要，更多信息按需展开。Ant Design 默认 `Table` 不能自动复制该交互，需要明确选择响应式列、移动端列表或自定义渲染。320px 窄屏可用性应作为独立验收，不是“用了组件库就自动解决”。

### 4. 全局 CSS 与弹层机制需要清理

现有 `input`、`button`、`table`、`th, td`、焦点规则及 `.form-grid label` 等较宽选择器，可能作用于 Ant Design 内部 DOM。直接叠加两套样式容易出现双焦点环、控件高度和对齐变化、复选框尺寸异常、弹窗嵌套间距冲突。应界定旧样式作用域、统一主题 Token 与组件定制，不依赖堆叠 `!important`。

当前 Modal 自管焦点陷阱、关闭后焦点恢复、滚动锁；Radix Select 还通过 `data-select-popup` 避免一次 Escape 同时关闭下拉和弹窗。迁移时不应把两套焦点管理简单嵌套。下拉挂载容器、层级、滚动、遮罩关闭、标题/内容/页脚分区及 320×480 短屏均需验证。

### 5. 测试需要适配，但业务断言不能削弱

现有测试既有按角色/标签的业务定位，也有 CSS 类、原生复选框和几何属性断言；组件 DOM 改变后，不能只把失效断言删除。组件确认框还会让监听浏览器 `dialog` 的测试失效，需改为操作实际确认弹窗。

至少保留：配置新增/编辑/取消、后台刷新不覆盖草稿、409 冲突、URL 前进后退、当前页批量范围、付费确认、预算授权不自动排队、重复提交/幂等、只读权限、失败恢复、密钥遮罩/复制、下拉键盘、Escape 和焦点恢复、窄屏及短屏。Portal、动画、虚拟列表及尺寸观察还可能需要调整 JSDOM 测试环境和等待条件，不能通过全面模拟组件绕过真实交互。

### 6. 依赖、性能与发布

当前未安装 `antd`，已有 React 19.2、React Router 7、TanStack Query 5、Radix Select 与 lucide-react。实际执行 `npm view antd version peerDependencies engines dist.unpackedSize --json`，当前 registry 返回 `antd` 6.7.0，React 与 ReactDOM 的 peer 范围为 `>=18.0.0`。这说明声明范围包含当前 React，不等于安装、浏览器、测试和全部 API 已验证；正式选择应锁定具体版本并检查官方版本文档和升级约束。本轮没有执行安装。

组件库可能增加公共依赖体积，CSS 删减、按需使用和分块会影响最终结果，需要比较迁移前后 gzip、首屏和交互表现；npm 包解压大小不等于浏览器下载体积，不能据此估算首屏。当前已存在约 500 kB 主包告警，不应承诺迁移会自然解决。

纯 UI 迁移原则上仍可仅发布前端静态资源，备份并保留旧哈希文件、原子切换入口，不需停 Worker 或迁移 SQLite。但必须发布与版本相匹配的完整前端产物；控件语义变化仍可能间接产生错误请求，不能把“后端没改”当作功能零风险。

## 哪些内容不需要一起重写

- API Service、鉴权、React Router、TanStack Query、查询键、重试、幂等键与服务端业务规则应尽量保持。
- `RecoveryBudgetPanel`、`ReviewRecoveryPanel`、`ConnectionChecks`、`UnsavedChangesGuard` 等领域组件不会因为引入 Ant Design 而消失；可以保留业务封装，只替换内部基础控件。
- 页面布局和普通语义 HTML 不必全部替换为 Ant Design；“使用同一组件库”不等于禁止 `div`、`form`、文本和自定义业务内容。
- Ant Design 基础组件库不等于完整图表库；现有图表和评审内容展示可先保留。是否引入图表库、ProComponents 或更换图标是独立范围，不应默认打包进来。
- 当前蓝白主题可通过统一主题配置延续，但组件边距、控件尺寸和 DOM 会变化，不能承诺像素完全不变。

## 工作量判断：用于决策，不是排期承诺

| 范围 | 初步量级 | 边界 |
| --- | --- | --- |
| 仅安装并在一两个页面试用 | 小 | 不等于完成全站迁移，容易形成长期两套组件。 |
| 保留领域状态与现有封装，逐类替换全站通用 UI | 中到偏大 | 更符合本项目“视觉统一但功能不变”的目标。 |
| 同时重写所有 `Form`、确认流、表格移动端和导航 | 大 | 叠加状态重构，回归风险显著增加，不建议作为默认范围。 |

若正式目标为全站通用控件迁移、保留业务状态和 API，并包含表格、确认交互、CSS 清理及完整回归，单名熟悉项目的前端开发者可暂按 **约 10～20 个工程人日** 作为讨论量级，实际日历时间取决于资源与评审；原型前不宜细化到完成日期。该估算不是承诺，也不包含额外功能、图表重建、ProComponents、后端改造或设计大改。应先用复杂仓库表单、带批量操作的任务表格和额度确认弹窗校准后再正式排期。

## 对后续规划的建议边界

后续规划建议以“Ant Design 统一通用 UI + 保留项目业务封装和状态逻辑”为目标，而不是一次性重写所有页面。确认范围时分别决定：是否使用 Ant Design `Form` 接管表单状态、是否替换原生确认流程、移动端是否保持现有摘要卡片、图标/图表是否纳入。当前只是说明这些决策的影响，不执行迁移。
