记录日期：2026-11-07。关联事项：PI-20261106-008。依据：[五步实施方案](review-partial-review-plan.md)。

## 1. 本次交付边界

- **代码修改：**独立补审批次、SQLite 排队、固定输入执行、候选版本与安全摘要接口已实现。
- **本地验证：**临时数据库和合成 Git/OCR 适配器验证范围、配置、幂等、调度、取消、清理与迁移；实际结果在第五节记录。
- **部署生效：**未部署、未重启服务、未迁移业务库，未调整生产超时/预算/并发或模型，也未调用真实模型或重审历史任务。

本次是第三步的隔离核心，不是第三步完整交付或可直接生产启用的补审功能。`Settings.review_recovery_enabled` 默认为 `False`，只供隔离测试显式注入，尚无生产环境或页面配置入口。

有效结论消费者尚未统一。列表、详情、统计、反馈、问题跟踪、导出与通知继续读取初审事实；不会出现只有详情提前变成 complete、统计仍沿用 partial 的半接入状态。候选接口始终返回 `consumer_integration_ready=false`，仅提供覆盖与发现数量，不返回完整发现、来源映射、执行令牌、工件路径或配置快照。

## 2. 执行与持久化

1. HTTP 继承管理员鉴权，仅查询资格、提交命令或登记取消，不执行 Git、OCR、模型或通知。服务端从可信覆盖推导全部剩余失败项，客户端不能指定任意文件路径。
2. schema 43 新建 `review_recoveries` 和 `review_recovery_aggregates`，不回填历史任务。命令保存父任务、初审尝试、源候选版本、批准路径与根 item ID、摘要、幂等键、有限 token 和时间预算。
3. 工件锁与 SQLite 活动唯一索引共同裁决重复点击和不同幂等键并发；相同键/相同命令返回原批次，键冲突拒绝。全量重审与活动补审互斥。资格查询不是原工件和 Git 已验证的承诺，最终核验在 Worker 中完成。
4. Worker 使用现有唯一模型槽，正常评审、补审、合并前评审、模型诊断不会并发调用模型。正式进程仅使用协调器，旧 `run_once` 作为串行入口不与协调器混用；领取以 SQLite 事务及一次性执行令牌裁决。
5. 执行锁定原始 base/head，验证根尝试原始工件的受控路径、大小、JSON、输入 SHA、覆盖与发现，并核对持久化快照、当前配置、实际装配设置、仓库规则摘要及 Git 可达性。配置或输入漂移明确失败，不跟随新分支头、不重建提交，也不降级为全量评审。
6. 新 checkout 保留完整上下文，HOME 与工件目录隔离。补审只复制实际规则后排除已完成/豁免项；保持项目高于仓库、仓库高于全局的优先级，与换行过滤依次叠加。原始预览须精确等于源 selected，子集预览及正式 manifest 须精确等于剩余集合，未知 CLI 版本拒绝调用模型。
7. 完成事务再次比较源尝试、聚合版本、摘要与令牌；只允许 complete/partial 子结果推进候选，拒绝越界发现、覆盖漂移、新豁免/复用及预算不确定。无完成进展不推进版本，保留初审、原通知、原反馈及原始工件。
8. 聚合保持根 item ID 和初审发现顺序，新增发现记录补审批次及评论索引，精确重复发现保留附加来源。逐批次保存可信用量，候选用量为空，不把累计 token 写成新一次模型消耗；没有可信 JSON 时保持未知，不填零。

## 3. 失败、取消和保留

- 补审失败仅结束本批次，不重跑初审、不自动重试、不发送补充通知；错误保存固定领域码或允许的故障分类，不保存外部正文。
- 排队取消立即结束，运行取消由 Worker 和最终事务优先裁决；迟到成功不覆盖取消，旧令牌或删除后的结果不复活任务。
- Worker 中断不被误写为用户取消；独占重启恢复把 running 补审记为中断失败，不重复调用模型。
- 活动运行和七天内排队批次阻止初审工件清理；七天排队失效释放引用，领取时记为 stale。工件失效不触发全量回退。项目删除级联清除批次/候选，遗留目录交由既有孤儿工件清理。
- 聚合插入与批次终态同事务。数据库写入失败时回滚，不留下完成假象；若异常最终落库也失败，则由协调器停止及下一次独占恢复处理，不能静默继续或宣称成功。

## 4. API 与后续接入顺序

| 接口 | 事实边界 |
| --- | --- |
| `GET /api/jobs/{job_id}/recovery-eligibility` | 返回数据库资格、源尝试/版本与剩余数；默认 reason 为 feature_disabled。 |
| `POST /api/jobs/{job_id}/recoveries` | 管理员显式预算与幂等命令，202 只表示排队。 |
| `GET /api/jobs/{job_id}/recoveries` | 稳定 ID 游标分页，最多 100 条，返回批次状态与安全用量。 |
| `GET /api/jobs/{job_id}/recovery-candidate` | 只读候选覆盖摘要，明确不是平台有效结论。 |
| `POST /api/review-recoveries/{recovery_id}/cancel` | 持久化取消意图，不在 HTTP 中发进程信号。 |

下一阶段先建立统一有效结论读取入口及跨版本发现身份，接通任务查询、统计、报告、反馈和问题跟踪，再接页面按钮与独立补充通知；未支持的 GitLab 发布路径继续关闭。不能单独给候选挂按钮后便启用功能。

上线另需业务库副本迁移/恢复演练、成对备份、协调在途任务、同版 API/Worker/monitor/前端部署和真实只读验收。schema 43 的临时库测试不等于业务库已升级。源头超时仍需有预算的真实网关关联调查，补审机制不能被描述为根因修复。
