# 后台配置与接入操作

> 当前使用说明；项目结构与功能边界见[项目总览](project-overview.md)，其他资料见[文档索引](README.md)。

本文依据飞书《Review后台配置操作手册》的四块配置流程编写，并按本项目的 Alibaba Open Code Review（OCR）评审引擎调整模型设置。配置保存在 `OCR_APP_DATA_DIR/app.db`，凭据使用 `OCR_APP_MASTER_KEY` 加密；修改后台配置后无需重启 API 或 Worker。

主导航保留“运行概览”“评审任务”“待跟进问题”“合并前审查”“项目配置”“系统设置”和“访问权限”。模型、飞书及规则配置集中在“系统设置”的三个标签页，默认进入“Agent 模型”，标签可刷新及通过浏览器前进、后退定位。旧的 `/feishu`、`/review-rules` 地址分别跳转到对应标签；配置历史与运行监控不再提供菜单入口，原页面、后台能力及数据仍保留。

评审效果的关键指标和趋势合并到“运行概览”，类别与项目统计默认折叠。原 `/effectiveness` 地址跳转到概览并保留项目、时间筛选。修复数来自人工状态标记（包含批量操作），不表示系统验证了代码修复；统计规则与历史数据不变。

运行指标读取全部 SQLite 任务，而非最近 200 条记录。“待关注评审”包含失败和部分完成；仅同一项目、MR、头提交与基线后来产生完整结果时，旧异常才不再计入待关注。失败任务总量按每个任务的最新持久化状态计数，不是失败尝试次数；不同配置重审创建新任务时会保留旧失败记录，同配置在原任务重审后则随任务状态变化。飞书发送失败独立统计，可从指标跳到对应任务，避免为重发通知再次调用模型。

系统设置中的审核规则、模型和飞书编辑支持未保存提醒。切换标签、侧栏、浏览器前后退或退出时可取消离开并保留草稿；刷新或关闭窗口使用浏览器原生提醒。草稿和新录入密钥仅保留在内存中，确认放弃或关闭浏览器后不会恢复。保存中暂时禁用表单，避免新输入被保存响应覆盖。

## 1. 新增并启用模型

打开管理台的 **系统设置 → Agent 模型**，点击“新增模型”，填写配置名称、OCR Provider、精确模型标识和 API Key。使用 OCR 内置 Provider 时，Base URL 留空；连接 OpenAI 兼容服务时填写无凭据的 HTTPS API 根地址，通常以 `/v1` 结尾，不能填写只返回网页的站点首页。平台会在隔离的 OCR 配置目录中建立自定义 Provider。保存后在列表中点击“启用”，再运行“测试模型”。模型可在列表中编辑；编辑时 API Key 留空表示保留原密钥。系统同一时间只启用一个模型；首次启用可处理此前积压的事件，后续切换或修改启用模型时须先让队列清空，避免旧任务使用不同配置运行。

使用阿里云百练模型时选择 **百练 / DashScope**，填写百练控制台创建的 DashScope API Key 和该模型的精确标识，Base URL 留空。可按百练当前公开计费页填写计费币种及每百万输入、输出 Token 的单价；两项单价必须同时填写，也可以都留空。单价仅用于估算，不参与 OCR 评审任务去重，也不会修改已经开始的评审快照。详情页分别显示 OCR 返回的输入、输出及合计 Token；仅当本次评审保存了两项单价且 OCR 返回完整输入、输出用量时，才计算预估费用。缓存折扣、阶梯价、赠送额度和其他账单项目不在估算范围内，以百练实际账单为准。旧任务缺少运行时单价快照时不会按当前价格补算。

Agent 模型页底部的“管理操作”按每页 20 条展示，可翻页查看全部审计记录。审计只保存操作者、路由、对象、结果和时间，不保存请求体、密码或密钥。

本项目使用 OCR CLI，不使用文档中的 Codex 登录认证或 Responses API 配置。因此模型标识和 API Key 是必填项，自定义 Base URL 需兼容 OCR 的 OpenAI 协议。模型密钥不会出现在列表、审计日志或评审工件中。

评审问题说明默认通过进程配置 `OCR_APP_REVIEW_LANGUAGE=zh-CN` 要求模型使用简体中文。该设置独立于文件审核规则，不改变规则优先级；修改后需重启 Worker，已有结果不会自动翻译，按当前配置重新评审后才会生成中文结论。

## 2. 新增飞书配置

在接收审核通知的飞书群中添加自定义机器人，复制完整 Webhook URL。建议在机器人安全设置中启用签名校验，并复制同一机器人的签名密钥。打开管理台的 **系统设置 → 飞书通知**，填写配置名称、Webhook URL 和可选签名密钥并保存。

一个飞书配置可以关联多个仓库。修改该配置后，后续投递和连接测试会读取新值；删除配置会解除所有仓库关联，仓库及其评审历史仍保留。关联仓库后，可在飞书配置的编辑窗口发起连接测试；测试会向目标群发送一条消息。

## 3. 新增仓库

先在 GitLab 项目的 **Settings / Access Tokens** 创建项目访问令牌，设置到期时间，并授予读取代码和调用项目 API 所需的最低角色及 `api`、`read_repository` scope。令牌创建后应立即复制。

打开 **项目配置**，填写：

| 字段 | 填写方式 |
| --- | --- |
| 项目数字 ID | GitLab 项目首页或 Settings / General 显示的数字 ID。 |
| 仓库名称 | 管理台显示名称。 |
| 仓库路径 | 完整命名空间，例如 `team/order-service`。 |
| Clone URL | GitLab 的无用户名、密码和 Token 的 HTTPS 地址，例如 `https://gitlab.example.com/team/order-service.git`。 |
| 目标分支 | GitLab 默认分支，例如 `main`。 |
| GitLab Token | 上一步创建的项目或群组访问令牌。每仓库建议独立。 |
| Webhook Secret | 保存仓库时由服务端自动生成，随后在项目配置列表查看。 |
| 飞书配置 | 选择第 2 步创建的通知通道。 |
| Merge Request 审核 | 需要审查已合并 MR 时开启。 |
| 默认分支 Push 审核 | 需要审查直接推送到默认分支的提交时开启。 |

保存后立即加入运行时配置；飞书配置可暂不关联，之后在仓库编辑窗口关联。编辑窗口预填仓库名称、GitLab 地址、数字 ID、仓库路径、Clone URL、目标分支、飞书关联和事件开关，并提供 Git 与 GitLab API 连接测试。GitLab Token 和 Webhook Token 不在编辑表单回填明文，前者可单向替换，后者可按需查看、复制或轮换。项目数字 ID 或 GitLab 地址录错时，可在收到合法 Webhook 或产生评审事件之前直接修正；有待处理事件或评审任务时，暂不允许修改仓库来源或分支。HTTPS Git 拉取通过临时 `GIT_ASKPASS` 读取项目令牌；令牌不写入 Clone URL、Git 命令参数或本地 Git 配置。旧数据库中的 SSH 项目可读取历史记录，但继续运行前需要在项目编辑窗口补录独立 GitLab Token；管理台新建项目只使用上述字段。

项目编辑窗口分为“基础接入”“评审参数”“发布审查”“接入诊断”四个页签，切换页签保留当前窗口内的草稿，不会自动保存。基础接入、评审参数、合并前配置分别保存；基础接入保存后窗口保持打开，不丢弃其他页签的内容。GitLab 行内评论开关为自动保存，旁边单独反馈保存结果。关闭窗口、离开页面或刷新时，未保存内容会触发确认；确认放弃后内存草稿清除，不恢复密钥草稿。

评审参数和合并前配置首次读取失败时，不提供可保存的默认配置，应先点击“重新加载”。保存失败与读取失败分别提示，保存失败保留草稿，可核对原因后重试。后台重新读取不会覆盖正在编辑的评审参数或合并前草稿。

## 4. 配置 GitLab Webhook

在 **项目配置** 页面复制统一回调地址，并从对应仓库行查看或复制 Webhook Secret。进入对应 GitLab 项目的 **Settings / Webhooks**：

1. URL 填写管理台给出的 HTTPS 回调地址，路径为 `/api/webhooks/gitlab`。
2. Secret token 填写该仓库的 Webhook Secret。列表默认遮罩，可按需查看和复制。重新生成后必须同步更新 GitLab。
3. 开启 Merge Request 审核时勾选 **Merge request events**；开启默认分支 Push 审核时再勾选 **Push events**。
4. 保持 SSL verification 开启并保存。

GitLab 必须能访问回调地址。`127.0.0.1` 只适合本机开发，正式部署应由受控 HTTPS 入口仅转发 `/api/webhooks/gitlab`。不匹配的项目、分支或未启用事件返回 HTTP 204；匹配项目的错误 Secret 返回 HTTP 401。默认只在 MR 合并后入队；默认分支 Push 只审查快进更新，并将一次 Push 的 `before..after` 最终净差异作为一个任务，首次创建分支、删除分支和强制改写历史不会自动审查。

## 5. 验收与安全

在 **系统设置 → 审核规则** 标签页选择“全局规则”或具体项目后，可添加按文件路径匹配的审核内容，并配置额外纳入或排除的路径。规则条目按页面顺序匹配，首条命中生效；“同时保留 OCR 内置语言规则”对应 `merge_system_rule`。项目页面规则优先于仓库提交的 `.opencodereview/rule.json`，全局页面规则是仓库文件之后的兜底。保存后仅影响后续任务；已有排队或运行中评审时，系统会拒绝修改适用规则。页面下方保留最近 50 个规则版本，删除配置也会生成历史版本；恢复旧版本会新增一条恢复记录，同样受待处理任务保护。核对仓库文件规则时使用 `ocr rules check <文件路径>`；核对页面项目规则时，可将任务运行目录中的 `managed-rule.json` 传给 `ocr rules check --rule <规则文件> <文件路径>`。

“规则生效预览”接收仓库内的相对文件路径。全局规则范围须先选择目标项目；项目规则范围自动使用当前项目。请先保存规则再发起检查。Worker 拉取目标分支，在固定提交的隔离目录运行 `ocr rules check`，页面显示命中来源、路径模式、规则正文和提交短 SHA；此操作不调用模型，也不创建评审任务。结果代表该提交及检查时已保存的规则，不代表尚未保存的编辑内容。

GitLab 测试投递后，在 **项目配置** 列表查看最近验证时间，并结合 GitLab Webhook 的响应状态核对结果。未匹配的项目或目标分支、非合并 MR、关闭的事件开关和重复投递不会创建评审任务；错误 Secret 返回 401。服务端只保留最近 500 条脱敏诊断元数据，不保存请求体、令牌或原始标头。

需要合并前审查时，在项目编辑窗口启用“合并前审查”，并在 GitLab Webhook 中勾选 **Merge request events**。可以勾选纳入 MR 描述，并填写最多 3 份仓库内 `.md` 或 `.txt` 文档路径，每行一份，例如 `docs/review-context.md`；路径对应待审 MR 的头提交，文件须是普通文本文件，不能是符号链接。新建、重新打开或更新 MR 后，Worker 会核对 GitLab 当前提交版本，以目标分支共同祖先和 MR 头提交运行完整差异评审；提交或描述变化会建立新版本，配置变更也会使旧结果失效并重新排队。详情页只展示业务背景的来源和摘要，原文仅保存在受控运行工件中。当前实现只在管理页展示合并前结果，不向 GitLab 或飞书自动发布，也不阻止 GitLab 合并。合并后的 MR 逐提交评审仍按原开关独立运行。

在 GitLab 项目的 Webhooks 页面发送测试事件，确认管理台的项目配置列表最近验证时间更新；随后合并测试 MR 或向默认分支推送测试提交。到 **评审任务** 查看状态、耗时与消费，确认飞书群收到通知。MR 合并任务按提交展示，默认分支的一次 Push 只展示一个范围任务；漏投或历史 MR 可在同一页面按 IID 补触发。默认不向 GitLab 写回。需要 MR 行内评论时，在项目编辑窗口单独开启“GitLab 行内评论”，并确认项目令牌拥有创建 discussion 所需权限；只有能在 MR 当前 diff 中定位到新增行的发现会发布，其余显示“已跳过”。行内发布失败可在任务详情独立重试，不会重跑 OCR 或飞书通知。Push 任务不向 MR 发布。

开发模式 `OCR_APP_DEV_MODE=1` 仅适用于可信本机；正式环境必须设置 `OCR_APP_ADMIN_TOKEN`，并限制管理页网络访问。需要多人账号时，先在 **访问权限** 页面创建至少一名管理员，再启用“多人账号登录”。启用后共享管理口令立即失效，页面重新登录；可继续创建只读账号。管理员可调整角色、停用、重置密码或删除账号，最后一名启用管理员不能停用或删除。只读账号可查看运行结果，不能修改配置、重试任务或查看 Webhook Token。账号登录凭据只保留在当前浏览器内存中，刷新页面后需重新登录；审计表显示操作者，旧审计记录显示“旧记录”。需要回到原有本机或共享口令模式时，由账号管理员在同页关闭多人登录。`OCR_APP_MASTER_KEY`、数据库和备份都应按敏感文件保护。不要把 GitLab Token、Webhook Secret、飞书 URL、签名密钥或模型 API Key 写入 Git、截图、Issue 或日志。

飞书手册的 `service.env`、`projects.yaml` 和 `CODEX_*` 首次导入命令属于另一套实现；本项目当前通过管理台和 `OCR_APP_*` 进程配置接入，不会读取这些文件。运行服务和 Worker 的步骤见[部署说明](./deployment.md)。
## 6. 评审发现的就地处理

### 任务检索与重审

“评审任务”提供排队与运行、待关注、失败、部分完成及飞书失败快捷筛选；也可按项目、状态、MR IID、SHA 前缀、分支与时间检索。显式选择状态后会清除快捷视图，防止冲突条件导致意外空列表。列表显示当前尝试的发现数、最高级别和独立飞书状态；重审开始后不沿用上一次尝试的发现数。费用列名为“预估费用”，不是供应商实际账单。

管理员可勾选当前页终态任务后点击“重审所选任务”；提交前确认任务数与模型费用影响，每项入队或拒绝单独回显。补触发 MR 和手填任务编号的重审位于“补触发与高级操作”中。重新评审只安排任务，不自动修复代码；通知失败优先在任务详情点击“重发通知”。

SHA、分支与起止时间收纳在“更多筛选”，已生效条件显示为可单独移除的标签。任务、问题及合并前列表均可选择每页 25 / 50 / 100 条，并跳转到指定页；条数与筛选保存在 URL，刷新后保留。当前页重审只取消成功入队项的勾选，拒绝项保留，核对后可再次提交；请求期间不能改变选择、筛选或分页。未勾选任务且无操作结果时，不展示空的批量重审栏。

任务详情优先展示失败原因与评审发现；变更文件和排除范围、历史报告与对比、执行记录默认折叠。结束任务降低轮询频率，不影响独立 Worker 持续执行。

### 问题检索与详情

问题列表展示描述摘要，支持按描述、文件路径或精确问题编号搜索；百分号、下划线和引号按普通文本处理。桌面点击摘要或查看按钮打开侧栏，手机以全屏详情呈现。当前问题和筛选保留在 URL，关闭详情不清除筛选。合并重复项时先搜索并选择同项目待处理问题，再确认源和目标编号；不能跨项目合并。

出现记录和处理记录默认各显示最近 10 条，可逐次追加查看更早记录，不会删除历史。重复问题搜索在停止输入约 300 毫秒后提交，修改关键词立即清空原合并目标，防止用旧搜索结果误选。

在任务详情的 **评审发现** 卡片中，可以直接处理关联问题，不必再进入 **待跟进问题** 重复操作：

- **误报**：确认该发现不成立，将仍待处理的关联问题同步为“已忽略”，不再出现在默认待处理列表中。
- **已修复**：确认代码已经修复，将关联问题同步为“已修复”；按钮不会自动修改代码或验证修复。
- **有帮助**：只表示认可发现，不代表代码已修复或无需处理。

卡片中的问题链接展示服务端实际状态，仍可点击查看跨任务出现记录与处理历史。同一问题可能关联多个任务，关闭会影响这些任务共享的问题。反馈和问题状态在同一 SQLite 事务内保存，同时记录操作者与处理来源。

再次点击已选标记可撤销；若该问题最近的关闭决定来自本卡片，撤销或改为“有帮助”会恢复待处理。其他卡片或问题页后续作出的关闭决定不会被旧反馈覆盖；后续评审未发现同一问题也不会自动视为修复。

升级不会批量改写既有反馈对应的问题。历史误报或修复标记仍关联待处理问题时，卡片会提供 **同步处理** 按钮，点击即可重新确认并同步，无需跳转问题页。

### 批量处理跟进问题

在 **待跟进问题** 列表逐条勾选，或点击 **全选当前页**，然后选择 **批量标记已修复**、**批量标记已忽略** 或 **批量恢复待处理**。可以填写统一的处理说明，提交前会再次确认问题数量。仅修改当前页显式勾选的问题，不扩展到其他页；切换筛选或分页会清空勾选，已合并的问题不可选。列表每页默认 25 条，可切换为 50 或 100 条，接口每次最多接受 100 条。

批量修改与每条处理记录在同一 SQLite 事务内提交；任一问题不存在、已合并或状态出现冲突时，整批不更新。错误时保留当前勾选和说明，点击刷新后根据最新状态重新选择；重复提交相同目标状态不会重复生成处理记录。成功后会刷新关联任务卡片和评审成效统计。

批量“已忽略”表示关闭跟进，不会把所有关联发现的反馈改成“误报”，也不修改已发布的 GitLab 评论或飞书通知。问题处理与发现反馈仍分别保留各自的历史事实。

### 合并前版本与接入诊断

“合并前审查”默认每个 MR 只显示最新接收版本，可筛选项目、MR 和状态，勾选“包含历史版本”后分页查看旧记录。先确定最新版本再筛选状态，不会用旧成功版本替代当前失败版本。详情链接可刷新和分享。失败、部分完成、跳过、未结束、失效或缺少完整覆盖证明时，都不显示“未发现问题”；结果和上下文记录损坏时给出未知提示，不使整页崩溃。

进入“项目配置 → 编辑 → 接入诊断”，可核对已保存的事件开关、Git/GitLab 测试状态、最近 Webhook 验证、模型来源、飞书关联及最近接收事件对应的任务和错误。当前配置缺少有效测试时，不把旧测试成功显示为接入完成。打开诊断只读取本地事实，不自动调用 GitLab、模型或飞书；Git/GitLab 测试需主动点击，未生成任务时先核对事件过滤原因与 Worker 状态。

## 7. 备份恢复与保留

每日备份将 `app.db` 与包含主密钥的 `private.json` 成对保存，默认保留 90 天且至少保留最近两份。可以在备份命令中通过 `--retain-days 180` 调整期限。恢复命令仅写入一个**不存在的新目录**，不会覆盖正在运行的服务：

```bash
.venv/bin/python -m ocr_manager.backup --restore-from /path/to/backups/app-YYYYMMDD-HHMMSS.db --restore-to /path/to/restore-data
```

先核对新目录中的数据库与 `private.json`，停止 API、Worker 和 monitor 后，再将服务配置指向恢复目录。恢复目录与私有配置文件须仅当前用户可读。已删除项目的工件目录由 monitor 在工件锁释放后自动清理；原 `/operations` 管理员页面仍保留手动维护能力，但不再提供主导航菜单。
