# 自建评审 Agent 能力管理方案

规划日期为 2026-11-19。本文描述拟实施的产品行为。现有双评审设计见 [Agent 框架设计](review-agent-framework-design.md)，试点样本见 [试点验收记录](review-agent-pilot-acceptance-20261119.md)。

2026-11-20 实施入口及验收方式见 [能力管理操作指南](review-agent-capability-management.md)。

## 一、从页面完成一次调整

以「前端项目增加组件状态检查」为例，管理员在「系统设置 → 自建 Agent」复制当前方案，在草稿中选择已发布的前端检查 Skill，设置匹配 `.tsx` 文件时加载。管理员选一条历史任务预览命中文件、将加载的版本和允许调用的工具，确认后可发起一次独立试跑。预览只计算配置和匹配范围，试跑才调用模型。

管理员查看试跑结果后发布方案，在「项目配置 → 自建 Agent」为试点仓库选用这个版本。任务详情保留已有 OCR 结果，单独运行新版 Agent。点开某条 Agent 发现，可以追溯命中的 Skill、读取的差异或文档证据；在双评审对比区记录人工裁定。方案不理想时，把项目切回上个版本，历史比较仍可查看。

## 二、三个入口及其职责

| 页面 | 管理者能做什么 | 需要呈现的信息 |
|---|---|---|
| 系统设置 → 自建 Agent | 管理流程、内置工具、Skill 和 MCP 服务；将选定的版本组合成评审方案，保存草稿、试跑、发布、停用 | 当前发布版本、相对前版的改动、引用项目、试跑结果和操作者。已发布版本不可原地修改 |
| 项目配置 → 自建 Agent | 操作现有仓库试点开关，继承平台默认方案或固定某一发布版本，默认复用项目模型，也可指定 Agent 专属模型 | 保存前显示最终生效的流程、工具、Skill、MCP 和模型；平台默认版本变更时列出受影响的继承项目。任务详情的旧开关与这里共用同一条仓库记录 |
| 评审任务 → 双评审对比 | 选择按原配置重跑或按当前项目配置新跑，查看两路评审及人工裁定 | 区分「配置允许」「本次命中」「实际执行」，展示流程节点、工具调用、证据来源、失败和覆盖范围。旧任务缺少记录的字段显示「历史未记录」 |

## 三、四类能力如何管理

| 能力 | 页面可编辑的内容 | 执行约定 |
|---|---|---|
| 编排 | 首版展示当前逐页评审流程并支持版本选择。后续可在预设位置启用「加载 Skill」「补查代码」「查询规范」等节点，配置触发条件、执行顺序和失败处理 | LangGraph 负责执行已支持的节点。发布前校验必经的读取、证据校验和结果保存步骤、依赖关系和终止条件。自由画布可待出现预设节点难以表达的真实流程后再评估 |
| 工具 | 列出工具用途、可读范围和参数。内置 `read_diff` 是基础流程必需项，后续按项目选用已实现的固定提交文件读取、代码搜索等只读工具 | 开发者实现工具，管理员组合和授权。运行时按项目、提交、路径校验，记录工具结果摘要和证据位置 |
| Skill | 创建、编辑、预览、试跑、发布检查方法，管理名称、检查步骤、适用路径或文件类型和版本。支持先使用一个明确的匹配条件 | 后端按冻结版本加载命中的正文，复用现有项目规则作为基础。展示规则与 Skill 各自来源，记录命中与跳过原因。Skill 仅描述检查方法，无法自行授予工具权限 |
| MCP | 管理服务地址、凭据引用和项目可用范围；测试连接、发现工具、勾选允许项，设置超时以及失败时继续或终止 | 首个服务建议提供只读规范检索。Worker 执行连接测试和评审调用，按部署允许的地址与工具访问，服务返回只作证据。凭据进入既有加密机制，页面和运行记录只显示引用。结果带文档标识、版本或检索时间；服务不可用时展示影响范围 |

## 四、如何接入现有系统

1. **复用当前运行路径。** 现有 `review_prototype/graph.py` 提供开始、读取、评审、完成节点，`agent_review_worker.py` 消费任务并提交进度。先把该流程和 `read_diff` 登记为内置版本，再让现有 Worker 消费项目选定的方案。保留仓库试点授权和现有项目模型行为。
2. **SQLite 保存配置事实。** 新增能力及修订、方案及修订、项目选用关系；按次记录运行配置和节点／工具执行。平台发布、项目切换分别记录操作者、时间和前后版本。页面写配置或入队，耗时操作交给 Worker。
3. **入队时冻结，执行时校验。** 运行绑定方案及各能力版本、模型引用和配置摘要、代码提交和 OCR 来源。相同请求重复提交沿用现有幂等机制；同一请求键携带不同配置时提示冲突。草稿试跑记录独立身份并明确标记，不计入正式样本统计。原配置重跑检查绑定能力仍可用；凭据已撤销或能力被紧急禁用时给出明确原因。外部文档可变时展示当次检索版本，「按原配置」不承诺输出相同。
4. **兼容已有任务。** 升级后，既有项目默认解析到与当前逐页行为等价的内置方案，沿用原有模型策略和预算语义。已入队或历史任务按旧快照解释，不能用当前配置倒填。切换 Agent 方案仅作用于后续相应 Agent 运行。试跑与人工对照复用同一提交和已有 OCR 结果，不触发额外 OCR 或飞书投递。

## 五、实施顺序和验收

| 阶段 | 可交付的操作 | 验收条件 |
|---|---|---|
| 1．先看清、选得准 | 三个入口、内置流程和工具目录、项目绑定、Agent 模型选择、运行快照。沿用原有模型档案和仓库开关 | 无需手填环境变量；新任务详情显示与项目选择一致的版本；切换模型仅影响后续 Agent；旧记录可打开，试点关闭仍不能入队 |
| 2．发布并验证 Skill | Skill 编辑与发布、方案草稿、路径匹配预览、历史任务试跑与项目版本回退 | 同一提交分别用原方案及新增 Skill 试跑；命中和未命中文件均有记录；试跑不产生正式通知；回退后下一次运行使用旧版本 |
| 3．管理编排和工具 | 增加一个固定提交的只读文件工具，提供「需要跨文件证据时补查」节点，支持调整可选步骤并校验发布 | 用跨文件样本查看补查实际读了哪个文件、在哪个节点使用；基础读差异和结果校验不可跳过；越权路径或非法流程不能执行 |
| 4．接入首个 MCP | 服务登记、连接测试、工具发现、项目授权和运行证据 | 用一条依赖规范的样本核对文档引用；再验证服务超时、撤销授权和禁用工具时的运行状态、证据和页面提示 |

每阶段先在试点仓库验收。#611 可作为相同提交和 OCR 结果下的基线，再从已有样本选择一条跨文件任务和一条双路零发现任务。正确性按人工确认的成立、误报和漏报比较，同时记录覆盖、耗时与实际模型用量。已有样本本身不能证明新增能力提升了正确性。
