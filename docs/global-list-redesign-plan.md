# 全项目列表统一体验规划

> 关联事项：PI-20261108-003；关联基线：PI-20261108-002、PI-20261107-011。盘点日期：2026-11-08（北京时间）。初始交付为源码盘点与规划；用户确认后的实施范围见第 10 节，未发布。

## 1. 结论与范围

大部分列表可以沿用新版任务列表的紧凑结构，但应统一“信息层级与交互”，而不是统一所有业务字段、状态和数量。

- **业务工作列表**：任务、待跟进问题、合并前审查、合并事件、平台问题记录、优化历程。采用状态导航、常用筛选、紧凑表格和统一分页。
- **轻量配置列表**：项目、模型、飞书通道、配置历史、账号。复用表格与操作规范；按实际需要提供搜索和筛选，不为少量配置堆状态栏和统计卡。
- **内嵌记录与报告**：最近任务、投递、审计、聊天收件箱、性能分组、效果统计、详情证据。统一行密度、时间、展开、空错与分页规则，保留摘要、报告或证据各自的结构。

本轮覆盖 **11 类主列表（包含任务基准，其他 10 类）**，并补充内嵌列表。依据当前工作区源码、查询实现和既有规划，不把历史规划中的“待实施”直接当成当前现状。

新版任务列表已在上一事项完成开发与隔离验证，但没有部署证据。本规划以其源码设计为基准，不表示当前运行实例已加载新版，也不沿用上一轮测试结论为本轮全站验收。

### 1.1 本轮不做的事

- 不重做新版任务详情，不改评审、问题处置、重试或通知状态机。
- 不为了展示而推断负责人、自动修复、通道健康、执行耗时或部署成功。
- 不新增批量删除、任务级一键修复、拖拽列、自定义列持久化和通用导出。
- 不扩大聊天采集授权或历史范围，不自动测试模型、GitLab、飞书，不改 HTTP 接收端与 Worker 的职责。
- 不重写复杂配置编辑器及草稿守卫，不因局部迁移删除仍有调用方的旧组件。

## 2. 全局统一规则

### 2.1 页面骨架

```text
页面标题 + 一句话用途                         刷新 / 新建
┌─────────────────────────────────────────────────────┐
│ 状态导航：全部 N / 待处理 N / ……（业务需要时才有）     │
│ 常用筛选 + 搜索 / 查询 / 重置 / 更多筛选               │
│ 已生效的筛选条件（可单独清除，高级条件生效也可见）      │
│ 批量操作栏（支持批量且选择后才出现）                    │
│ 紧凑列表：主体信息 / 业务事实 / 关键时间 / 文字操作     │
│ 总数与范围                 每页条数 / 翻页 / 跳转      │
└─────────────────────────────────────────────────────┘
低频维护、补扫与危险动作：独立折叠区域，不占首屏主位置
```

不额外增加一排重复统计卡；“记录 / 优化历程 / 复盘”这类视图导航与列表状态导航分层，不能把两者合成同一组状态。

### 2.2 表格信息与视觉

| 规则 | 统一要求 |
| --- | --- |
| 主次关系 | 对象名称、编号为主行；来源、路径、版本等为次行。常规业务行以两行为目标，约 72～88px；配置与小表允许更紧凑，不锁死高度截断事实。 |
| 默认列数 | 优先 6～8 个业务列，不含选择列；是密度目标而非硬指标，不能为减列把重要事实全部放进详情。 |
| 字段取舍 | 压缩重复解释，合并同一对象的信息；不删除提交人、业务状态、关键时间及本页决策必需字段。长正文进入详情，完整内容有明确入口。 |
| 状态表达 | 颜色加中文文字，不单靠色点、图标或悬浮。业务进度、问题处置、验证、部署、通知各用自己的口径。 |
| 数量表达 | 明确“任务 / 问题 / 发现 / 阶段 / 记录”的单位；未知显示“待确认”或 `—`，不填零、不显示绿色成功。 |
| 时间 | 对外明确所用时区；当年可显示月日时分，跨年显示年份，完整时间可点击或键盘访问，不只靠鼠标悬浮。保留创建、接收、最近发现等原始含义。 |
| 操作 | 常用操作保留“详情 / 编辑 / 重试”等文字；低频动作收进更多，危险操作明确后果。行可辅助点击，但必须保留可聚焦的链接或按钮。 |
| 外观 | 沿用现有灰白蓝、字体、设计变量与 Ant Design；统一间距和对齐，不另起主题、不新增组件库。 |

**耗时 / 尝试和创建时间继续作为任务列表的默认可见事实。** 其他页面按业务保留真实的次数与时间：问题显示出现次数和最近发现，事件显示尝试次数和接收时间。配置列表不凭空增加耗时；“出现次数”也不能改名为“尝试次数”。

### 2.3 筛选、分页与详情

1. 状态导航即时生效；离散 Select 条件原则上即时生效，文本与日期范围通过查询提交。同一筛选事务只更新一次 URL；任务等现有草稿式筛选先保留，不机械改变。草稿未提交时，列表、数量和条件标签仍只代表已生效条件。
2. 常用条件默认不超过一行至两行；时间范围、SHA、历史范围等低频条件折叠。收起后仍显示已生效条件，重置不能误清当前视图或其他内嵌列表参数。
3. 可分享的筛选、页码与详情定位放 URL；修改条件或每页条数回到第一页，浏览器前进后退、刷新和详情返回保持上下文。按服务端现有上限选择条数，不直接把所有接口改成相同上限。
4. 服务端分页列表的总数和状态数量来自全部匹配数据，而非当前页。完整配置数组可先在本地筛选、计数和分页；最近 100 条接口只能标明最近范围。
5. 简短单项排查优先复用现有 Drawer；复杂编辑与证据继续使用独立详情。返回参数使用白名单和站内路径，不把密钥、正文或任意外部返回地址写入 URL。
6. 单条查看不应破坏批量选择；更换筛选或分页按已有契约清空选择。执行确认期间冻结目标与版本、锁定范围，冲突保留输入，不增加跨页全选。

### 2.4 移动端、错误与刷新

- 1440 / 1280px 以完整表格验证；768px 调整筛选排列；390 / 320px 的业务工作列表采用紧凑摘要。必要时仅表格局部横滚，不让整页横溢。
- 手机摘要直接显示对象、业务状态、关键问题事实与关键时间；任务额外保留耗时 / 尝试。不能把所有核心列统一藏在“更多”。统计分组和证据对比表可保留局部横滚。
- 区分首次加载、确实为空、无匹配、无权限、请求失败、旧缓存刷新失败；失败不显示“共 0 条”，旧数据保留时标明未刷新和对应范围，不能与新条件的数量混用。
- 状态导航支持键盘，筛选有标签，Drawer 有焦点进出，展开入口可触达全文；触控和放大字体下不依赖 hover 才能理解关键限制。
- 沿用资源的轮询策略，不因通用表格让所有页面高频轮询。隐藏分区停止无意义查询；刷新不得覆盖编辑草稿、冻结确认或当前选中详情。

#### 待跟进问题的业务保护

- 默认状态仍为 `open`；“全部”现有语义排除 `merged`，应显示为“全部（不含已合并）”或明确范围说明。已合并作为独立历史范围，不能悄悄纳入全部并允许批量处置。
- “提交人”保留可见，不改称负责人；路径在摘要次行，长路径有查看完整位置的入口。问题原文及出现 / 处置历史留在现有 Drawer，不丢证据。
- 批量栏仅选择后出现，继续复用 `useIssueBatch` 的目标冻结、冲突和只提交一次语义。查看详情不清选择，筛选 / 分页变化清选择。
- `fixed` 是人工记录为已修复，不代表系统验证；“有帮助”反馈不等于关闭。处置、重开、合并后，需要核对问题、任务摘要、详情和统计等相关缓存的统一失效，覆盖所有入口，而不只新列表按钮。

#### 合并前审查的业务保护

- `latest_only=true` 时先按项目和 MR 确定最新记录，再应用状态筛选；不得为凑成功数量，回退到历史最近成功版本。导航数量与列表使用相同范围。
- 部分完成、被取代、取消、跳过与失败不等于当前 MR 通过。零发现同时保留覆盖、排除和豁免限制，不逐行重复无关长句。
- 目前没有等同于合并后问题库的处置关联，也没有可直接使用的执行耗时 / 尝试契约。首版不显示“全部已处置”，不使用接收时间推算耗时；如要扩展，另立持久化事实与验证范围。
- 保留已经存在的 Drawer 与 URL `review` 定位，不重复开展“详情改抽屉”工程。服务端摘要失败或未知时显式说明，正文按详情读取。

#### 合并事件的业务保护

- 事件“已处理”仅说明接收 / 触发流程结束，不代表评审完成，更不代表问题已修复；关联任务显示真实数量及最新任务入口，不把最新一个当成全部。
- 长诊断显示短摘要与“查看诊断”，完整内容在安全的详情区域；“需要处理”与重试条件沿用事件状态，不把重试入队成功说成恢复成功。
- 原有历史 MR 补扫继续在折叠区；保留日期上限、目标与后果确认，扫描结束不冒充产生的任务已完成。HTTP 只入队，Worker 执行耗时操作。

#### 问题记录与优化历程的业务保护

- 问题记录必须把 **代码修改、本地验证、部署生效** 三个事实分别保留为可见列，不能合成一个绿色“已完成”。处理进展继续沿用待处理、排查中、已完成方案、待验证、已解决、暂缓，不能把“待验证”擅改为验证通过。
- 默认归档范围保持未归档；归档不是问题状态，数量必须保留该范围。记录 / 主题与复盘是不同视图，不用复盘累计数量代替带搜索条件的列表数量。
- 主题进展与关联问题状态分离；“已完成 2 / 4 阶段”明确按阶段计数，可同时存在多个进行中阶段。无阶段显示“尚无阶段”，不显示 100%。
- 首版只显示真实关联问题总数，不新增“关联问题全部已解决”的推算；阶段证据和三维交付事实保留详情。详情返回增加来源筛选白名单，保留当前页与视图。

#### 配置数据与危险操作保护

1. 项目、模型、通道、账号当前返回完整数组，可以本地筛选和分页，数量标明对应配置对象；规模增长后再改服务端，不一开始造万能查询后端。辅助查询失败不能被解释成“未配置”“零关联”或健康。
2. 项目接收开关与接入就绪度是两个维度；`ready / needs_check / paused` 不与 enabled 强行合成单一互斥状态。接入就绪查询保留配置版本匹配；Token 默认不拉取明文，查看仍走受保护单项接口，不写 URL、日志或列表缓存。
3. 模型列表单价包含输入 / 输出与币种，未知不填零。保存、启用、连接测试分开；启用仍受队列条件校验，不因压缩操作绕过约束。未启用模型不能分享当前启用模型的测试成功标记。
4. 飞书签名“已配置”不表示通道可用；通道存在也不表示某条通知送达。测试会真实发消息，必须显式触发。删除通道说明解除绑定后果，关联名称加载失败时显示待确认。
5. 配置历史恢复会写新版本，不恢复模型启用状态，也不保证外部已撤销的密钥仍可用。不可恢复的原因应可见，不仅依赖 disabled 按钮 hover。对象名称查询失败不能推断对象已删除。
6. 删除项目可能关联清理事件、任务与投递，不能为了统一列表简化确认；最后管理员、禁用、密码重置和会话失效继续由后端约束，不增加账号批量删除。保留现有独立保存、自动保存和离开守卫。

## 5. 数据与接口专项

### 5.1 状态数量必须先确定范围

当前任务查询已有 `status_counts`；待跟进问题、合并前审查、事件、平台问题记录和优化主题尚无同等列表状态数量，不能仅添加前端标签便宣称完成。

统一计算规则：状态数量忽略当前状态导航及分页，但保留其他已生效条件。`total` 仍是当前状态与全部条件下的匹配总数，不能强行让“全部”数量等于当前页或当前状态的 total。

| 列表 | 状态数量必须保留的关键条件 | 特殊范围 |
| --- | --- | --- |
| 待跟进问题 | 项目、级别、搜索等 | 普通范围排除已合并；独立历史范围单独计数，不能通过忽略 status 意外放开 merged。 |
| 合并前审查 | 项目、MR、`latest_only` | 先确定每个 MR 最新记录；显示历史版本时数字也明确为历史记录。 |
| 合并事件 | 项目、MR、接收时间区间 | 统计事件，不用关联任务数替代。 |
| 平台问题记录 | 搜索、类型、分类、归档范围 | 不复用全库复盘累计；归档维度与处理进展分开。 |
| 优化历程 | 搜索、分类、归档、关联问题条件 | 统计主题，不把阶段或关联问题数算作主题数。 |

其他维度如后续也展示数量，须各自声明是否忽略自身筛选，不自动套用状态规则。全量接口可先提供不带数量的状态切换；数量未经后端验证前不展示假的零或当前页数量。

### 5.2 最近 100 条不是全历史

| 数据源 | 当前范围 | 第一版可接受方案 | 完整目标 |
| --- | --- | --- | --- |
| 配置历史 | `config_history.py` 查询 `LIMIT 100` | 明确“最近 100 条内筛选”，禁止标成全历史总数。 | 优先增加服务端分页、真实 total 与过滤；如需保持旧数组契约，可新增查询端点，不静默破坏旧调用方。 |
| MR 补扫申请 | `event_search.py` 最近 100 条 | 保留最近申请小表并明确范围。 | 数据规模需要时新增分页与历史查询，不在客户端伪造下一页。 |
| 告警投递 | `alerts_api.py` 最近 100 条 | 标明最近投递，状态筛选只针对已加载范围。 | 新增分页 / 过滤查询，与告警当前状态和配置接口分离。 |

配置历史的真实分页虽随配置页验收，也可前置开发；补扫和告警不必阻塞第一批高频业务列表，但范围说明不能延后。

### 5.3 列表摘要与性能

1. 合并前审查新增安全摘要：发现数、最高级别、覆盖结论、结果是否可用、必要的失败摘要。字段名与空值规则在实施时定稿；不逐行请求详情，不把完整模型正文当表格数据依赖。
2. 主题已有阶段和关联数组可支持首版摘要；后续规模增长时改服务端批量聚合，减少列表负载。关联问题“已解决数量”不是本轮必需项，若引入必须按持久化状态批量查询，不能只看主题完成。
3. 新增分面与分页尽量在同一读快照中取得，采用批量查询并检查索引与查询计划。配置辅助状态有独立完整性，不因主列表成功就当辅助结果成功。
4. 保留取消请求、旧结果隔离、权限和资源范围；变更接口同步响应契约、OpenAPI、前端类型和自动化测试。纯只读展示不要求数据库迁移；若新增持久化字段再独立评估。
5. 第一批先记录响应大小、查询耗时、请求数与构建包体基线，再对比改造结果；不预报减半或达成未测的性能数值。

## 6. 工程复用方式

目标是复用小型展示与交互基础，而不是建立接管全部业务的万能 CRUD 页面。

| 可复用能力（建议名，尚未创建） | 职责 | 明确不负责 |
| --- | --- | --- |
| `ListSurface` | 单主卡布局、工具栏与表格区域间距 | 不内置业务查询、权限或 Mutation。 |
| `ListStatusNav` | 状态文字、可选数量、键盘与窄屏布局 | 不决定业务状态、数量公式或 URL 参数。 |
| `ListFilterBar` | 常用 / 高级筛选布局、已生效条件入口 | 不接管筛选草稿、日期语义或 Query Key。 |
| `ListPagination` | 已知 / 未知总数、条数、翻页、跳页、范围说明 | 不把未知转零，不切片服务端数据，不突破接口上限。 |
| 时间与双行单元格 | 统一长文本入口、主次样式、时区和缺失值 | 不把创建、执行、接收、更新时间互相替代。 |
| 查询状态展示 | 首次加载、空、无匹配、失败、旧数据刷新失败 | 不自动重试写操作，不掩盖旧数据范围。 |

先从已有 `JobsPagination` 和任务样式中提取稳定部分，保留兼容包装与任务可访问名称，回归现有调用方后再迁移其他页。各页的列定义、状态标签、URL 和业务 Hook 继续归各页所有，不创建跨页重复状态 Store。

新增或重设计的 Button、Input、Select、Table、Pagination、Tag、Drawer、Modal 统一用 Ant Design。页面 CSS 仅做作用域内布局，复用设计变量，不用全局选择器或 `!important` 兜底。复杂表单不在本次同时改为另一套状态管理。

同路由多列表采用参数命名空间：保留 `theme_`，审计等新参数有独立前缀；配置设置继续保留 `tab`。不把 Token、模型密钥、完整通知地址、聊天正文放入查询键的持久化层、URL 或日志。

## 7. 分批落地与交付边界

| 批次 | 范围与依赖 | 本批可独立交付结果 | 验收重点 |
| --- | --- | --- | --- |
| 第 0 批：建立基线 | 保护现有任务列表，冻结状态 / 数量范围与字段去向；提取实际有多个调用方的基础组件。 | 统一规范、组件最小集合与任务页无回归；不是再做一次任务页重设计。 | 任务问题口径、耗时 / 尝试、创建时间、手机摘要与冻结确认不退化。 |
| 第 1 批：高频工作入口 | 待跟进问题 → 合并前审查 → 合并事件；各页配套分面 / 摘要接口，可逐页验收。 | 三页紧凑列表、可信状态数量、筛选与详情返回一致；最近范围明确。 | 问题合并 / 处置、MR 最新版本、事件重试及错误不显示零。 |
| 第 2 批：平台跟进 | 平台问题记录 → 优化历程；保留三视图与归档，补列表分面。 | 长卡片变紧凑工作表，三维交付事实直接可见，阶段 / 关联摘要可扫描。 | 三维不合并、归档 / 主题参数独立、历史证据与返回条件不丢。 |
| 第 3 批：配置管理 | 项目 → 模型 / 飞书 → 配置历史 → 账号；可先做配置历史真实分页。 | 轻配置列表统一，密钥按需，长关联 / diff 不撑行；账号保持简单。 | 密钥与权限、草稿 / 409、启用约束、恢复 / 删除后果、真实历史 total。 |
| 第 4 批：内嵌与收口 | 首页小表、投递 / 审计 / 聊天、反馈 / 报告及详情证据；按使用频率迁移。 | 全站主要列表体验一致，低频区不抢首屏，保留报告与证据结构。 | 最近范围、聚合分母、聊天授权、隐藏轮询、样式隔离与完整证据。 |

默认先做第 0～1 批，收益集中在日常“找问题、看审查、排事件”。平台台账使用更频繁时，可将第 2 批提前，但不合并不同业务的数据口径。每批分别记录代码、本地验证和部署，不进行一次性全站替换。

规划未给出固定工期：新增分面、历史分页、测试补齐的成本高于单纯调表格，应在接口与组件范围冻结后再按批次估算，不把所有页面都列成纯样式工作。
