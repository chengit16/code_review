## 后端契约与安全

schema 52 为连接记录增加模型/通知目标与内部连接指纹，迁移保留历史记录但不补造当前版本证据。入队、执行参数读取和完成写回分别校验，修改连接字段使旧通过失效；改名称/单价不失效。默认切换不改变指定目标验证，不自动调用模型。

资料查询为管理员显式创建 SQLite 临时队列，令牌使用原主密钥加密，仅供指定 HTTPS GitLab 主机；不复用其他项目凭据，不在 URL、列表或审计回显。HTTP 只入队，Worker 读取固定项目 API、禁用重定向、15 秒超时、响应上限 1 MiB，只保存核对身份后的白名单资料。队列最多 10 条，15 分钟过期，完成/取消/恢复中断均清除凭据，无自动外部重试。允许企业内网 GitLab；这不是任意公网用户的 URL 代理，管理 API 须按部署要求隔离。停止等待不能撤回已经发出的只读网络请求。

当前配置摘要仅描述后续任务的已保存事实；仓库规则文件须执行时按对应提交读取，历史结果以原快照为准。部署摘要不暴露密钥、私有配置路径或命令参数，API 进程摘要不证明 Worker 一致。

## 发布与边界

51 → 52 须协调同库所有 API（包括备用端口）、Worker、monitor，不能只更新前端或让旧进程混写新版库。切换前确认无在途任务、成对备份数据库与私有配置，并在隔离副本验证迁移和凭据解密；保留旧前端。沿用同一主密钥，迁移完成按同版启动，核对 schema、完整性、历史计数、Worker 心跳、新端点和只读浏览器。旧程序拒绝新版库，回退须停止进程并恢复备份、核对升级后新数据，禁止降低 user_version 或覆盖运行中的数据库。

本轮没有真实调用模型、向 GitLab 发送业务请求或向群发消息，不把连接准备或模拟验证称为端到端验收。飞书应用机器人、动态卡片及双向反馈仍属 PI-20261110-002 独立方案，没有凭本次授权接通。现有 Vite 主包仍有超过 500 kB 提示，未以调高阈值掩盖；后续拆包可独立优化。
