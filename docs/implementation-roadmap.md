# 项目完善实施路线

> 按已确认优先级拆分四轮实施。原排序第十项独立放入第四轮；第一、二轮先落地，第三、四轮暂不提前实现。

## 第一轮：恢复与基础交互

- [x] 将运行监控、配置历史接入“运维与审计”主导航。
- [x] 新增合并事件中心：全量分页检索、按项目 / 状态 / MR / 时间筛选、异常事件重试、按合并时间申请补审并查看 Worker 状态。
- [x] 合并前审查详情支持取消排队、停止运行和重试最新终态版本。
- [x] 清理已删除项目的遗留目录前明确展示候选数并二次确认；后端仍以任务锁和 SQLite 记录为准。
- [x] 管理 API 统一设置 30 秒请求超时，区分超时、网络失败、401 会话过期与无效响应，并保留服务端错误信息。

## 第二轮：质量门禁与工作台

- [x] 增加 GitHub Actions 门禁，运行后端 Ruff、mypy、pytest 及前端 ESLint、Vitest、构建。
- [x] 移动端任务列表改为紧凑摘要卡片，低频字段折叠，减少长表格滚动和首屏噪声。
- [x] 首页新增待办中心，优先显示事件恢复、评审异常、通知失败和合并前审查异常，并直达对应处理页。
- [x] 将管理操作审计从 Agent 模型配置移入“运维与审计”，避免审计与模型生命周期混在同一页面。

## 第三轮：接入体验与设计系统

- [ ] 为首次接入流程增加分步引导，覆盖模型、飞书、仓库、Webhook 和连接验证；每步可退出并可回到未完成位置。
- [ ] 建立统一设计变量和组件状态规范，逐页清理重复样式，保持当前绿灰视觉语言和窄屏可访问性。

## 第四轮：原第十项——对账与恢复可诊断性

- [ ] 对账持久化事件、评审任务、通知投递和工件目录，报告孤儿、缺失及状态不一致，不自动修复业务事实。
- [ ] 为 OpenAPI 契约增加前后端类型生成或一致性校验，提供本地和 CI 可执行命令。
- [ ] 记录恢复演练的备份标识、数据库版本、校验结果和操作时间；演练仍只在隔离副本执行。
- [ ] 贯穿请求、事件、任务、尝试和投递的关联 ID，并生成脱敏诊断包，避免包含凭据、原始代码及模型推理内容。

## 验收边界

- 每轮合并前执行与改动风险相称的后端、前端和浏览器回归；真实 GitLab、模型或飞书验收须在用户授权的测试项目执行。
- CI 只证明隔离测试环境中的自动化检查通过，不替代真实外部服务、备份恢复或生产部署验收。
- 仅将实际运行过的检查记录为通过；CI 本身还需等待远程工作流执行后才能确认成功。

第一、二轮本地验收：`uv run ruff check backend`、`uv run mypy backend/ocr_manager`、`uv run pytest -q`（222 项通过），以及 `cd frontend && npm run lint && npm test && npm run build`（28 项前端测试通过，构建成功）。Playwright 页面回归已尝试，但当前环境没有对应 Chromium 可执行文件，未计为通过；GitHub Actions 结果须在推送后确认。
