# 评审任务列表精简与问题处理展示规划

> 关联事项：PI-20261108-002。修订日期：2026-11-08（北京时间）。本文先列规划，末尾记录实施现状；部署状态以台账为准。

## 1. 设计目标与参考边界

保留耗时 / 尝试和创建时间，通过压缩重复文字与调整主次提升扫描效率，而不是一味删字段。

参考用户提供的 Bug 分析页面，采用灰白蓝、紧凑表格、带数量的状态切换、短状态标签和稳定对齐。继续使用本项目的 Ant Design、路由和查询状态，不搬用参考页面的业务模型、数据或验收结论。

不新增没有证据支持的负责人、修复环境、阶段灯或自动修复能力。不因参考页有“队列 / 入队日志”就另建导航；现有事件中心继续负责事件排查。

列表需要直接回答：哪次提交、谁提交、评审是否完成、问题是否已处置、通知是否送达、执行多久和何时创建。

## 2. 页面信息架构

1. 页头：标题“评审任务”；副标题“查看评审进度、问题处理与通知状态。”；右侧保留刷新。
2. 主内容卡片：状态切换、紧凑筛选、任务表格、分页，避免多层卡片和大块留白。
3. 高级动作：保留底部“补触发与高级操作”折叠区，不占常用浏览区域。
4. 批量动作：保留当前页选择；选择后显示操作栏，不永久占用一整行。保持权限、冻结确认目标与筛选变化后清空选择的约束。

不额外增加一排统计卡或重复标签导航。

## 3. 状态切换与筛选

### 3.1 评审状态切换

采用类似参考页的单行状态导航：

`全部 N ｜ 排队中 N ｜ 运行中 N ｜ 已完成 N ｜ 部分完成 N ｜ 失败 N ｜ 更多`

“更多”提供已跳过、已取消；窄屏允许换行或收纳，不压缩文字到不可读。排队/运行须考虑当前补审活动，不能出现初审已结束、补审仍运行却没有活跃提示的情况。

数量由后端按全部匹配记录聚合，不使用当前分页行数。统计应用项目、问题处理、通知及更多筛选，但忽略当前评审状态导航自身条件和分页。各项按统一的列表状态分类；活动补审、有效评审状态的优先级须在实施时统一到列表、统计和筛选，避免重复归类。旧 URL 状态参数保持可访问。

### 3.2 紧凑筛选行

默认展示“项目”“问题处理”“查询”“重置”“更多筛选”。项目和问题处理使用有可访问名称的紧凑 Select，不保留大块上下标签间距。提交后更新 URL，未提交的输入不参与统计。

- 问题处理：全部、有待处理、全部已处置、未发现问题、状态待核实。重审中尚无当前可用结果不归为“未发现问题”。
- 更多筛选：MR IID、提交 SHA、分支、创建时间区间、飞书通知状态；保留现有时间参数语义。
- 通知提供“发送失败”筛选，涵盖当前任务适用的初审和补充通知失败；不能只看主通知。
- 已生效条件可单独清除；筛选和状态变化重置页码，返回列表恢复条件。

“有待处理问题”是业务处置条件，不与评审失败混成一种状态。允许组合“已完成 + 有待处理”，直接找出已审完但还没有处理完的问题。

| 列 | 默认展示 | 次级信息及边界 |
| --- | --- | --- |
| 选择 | 当前页复选框 | 只读角色隐藏，仍由服务端授权 |
| 任务 / 项目 | 第一行项目名称与任务编号；第二行来源、分支、短 SHA | 来源为 MR !编号或 Push；长名称省略并可查看完整内容 |

| 问题处理 | 第一行“发现 N 条 · 最高高危”等风险摘要；第二行处置数量 | 发现数与去重问题数不强求相等，明确使用“条发现”和“个问题” |
| 飞书通知 | 已发送、待发送、发送失败等 | 当前补充通知失败须可见，不用主通知已发送遮盖 |

| 创建时间 | MM-DD HH:mm | 跨年显示年份，完整时间及使用时区可查看；不替换成更新时间或只用相对时间 |
| 操作 | 详情 | 固定右侧；待处理数字另作精确发现入口 |

费用不作为默认列，保留在任务详情；如后续确有高频需求再增加列设置，不在首版引入配置复杂度。

### 4.1 紧凑展示要求

- 常规任务主体以两行展示，目标行高约 72～88px，异常和无障碍放大允许自然增高，不设置截断重要内容的固定高度。
- 评审状态不再逐行附上完整“已完成选中范围，仍需留意排除和豁免”长句；实际存在范围限制时保留“有排除 / 有豁免”等提示，不一概隐藏。
- 问题处理允许第二行紧凑显示“待处理 6 · 已修复 3 · 已忽略 2”，零值项可省略；关键判断不依赖悬浮。
- 状态使用颜色加文字，待处理使用强调文本；不为每个数字套一个大标签，不照搬参考图的无文字阶段圆点。
- 桌面以 1440px、1280px 视口验证常用列；必要时仅表格横向滚动。移动端改为任务摘要，问题处理、耗时 / 尝试和创建时间仍直接可见，不全部藏入更多信息。

### 4.2 耗时口径

现有主值为初审累计执行，不是包含补审的全任务执行。首版沿用真实口径及服务端完整性标记，不能仅把标题改成“累计执行”造成误解。

排队中优先显示“已排队 X”，运行中按可信计时证据显示执行信息；缺失显示“未知”，不能补成零。初审和补审次数分开，补审采用实际执行次数，不把候选记录或取消的未执行批次冒充执行次数。显示在途耗时时，离开页面清理计时，排队期间不增加执行秒数。Worker 中断导致的历史未知仍须可见。

## 5. 问题处理状态与交互

以下数字仅为规划示例，不代表真实任务事实。

| 事实 | 展示文案 |
| --- | --- |
| 11 个关联问题，6 个开放、3 个已修复、2 个已忽略 | 待处理 6 · 已修复 3 · 已忽略 2 |
| 已无开放问题，9 个已修复、2 个已忽略 | 全部已处置 · 修复 9 / 忽略 2 |
| 当前可信结果完整覆盖、没有发现且没有未解释的范围限制 | 本次未发现问题 |
| 零发现但有排除或豁免 | 选中范围内未发现问题 · 有排除 / 有豁免 |
| 部分覆盖完成但零发现 | 暂无发现 · 覆盖不完整 |
| 排队 / 执行中且尚无可用当前结论 | 待评审 / 评审中 |
| 失败、取消或跳过且没有可用结论 | 未形成有效结论，并保留对应原因 |
| 关联缺失、合并目标异常或统计无法确认 | 状态待核实；已知待处理数可保留，不显示全部已处置 |

“已处置”包含人工忽略，不等于“代码已修复”。“有帮助”反馈不关闭问题。后续评审中不再出现，不自动认定已修复。关闭后重新打开，列表随持久化状态更新。

点击“待处理 N”进入当前任务的发现区，自动筛选对应开放问题的发现并保留返回列表条件；不是简单跳到无任务范围的全站问题页。某个问题对应多条发现时允许看到多条证据，入口需明确“按问题去重计数”。零发现状态不提供无效的待处理链接。

首版不新增任务级“一键已修复”或自动改状态；已有逐项反馈和问题处置入口继续负责人工确认与审计。

## 6. 数据与接口规划

1. 业务事实继续来自 SQLite，不以通知、任务成功或浏览器缓存推断处置。
2. 当前任务版本先确定有效初审 / 补审发现主身份，再关联问题；不累计所有历史尝试，不把未提升的候选发现混入当前统计。
3. 发现数量按当前有效结论计数；处置数量按关联问题最终目标 ID 去重。合并链解析须有界，识别循环和缺失；不能把 merged 直接算作已修复。
4. 接口增加问题处置摘要、完整性状态和筛选能力，并支持任务内开放发现定位；旧契约兼容缺失字段时显示待核实。
5. 后端批量查询，避免每行请求详情或逐个读取原始 OCR 正文；分页、总数、分面统计及筛选共享同一版本与口径，尽量在一致读事务内完成。
6. 问题反馈、人工处置、合并和重开后使相关列表与详情缓存失效；保留活跃任务短轮询与其他任务低频刷新，不复制第二套状态所有权。
7. 新增参数同步导航、报告入口所需的参数白名单及 OpenAPI / 前端类型；旧筛选链接不静默失效。服务端权限、事务和后台 Worker 边界不变。

## 7. 实施顺序与验收

### 阶段一：事实与统计

实现当前有效版本的问题聚合、状态分面数量、待处理筛选和关联完整性，先验证统计，再接界面，避免“样式先完成但数据误导”。

### 阶段二：列表与直达

调整卡片和筛选密度、紧凑表格及响应式摘要，保留耗时 / 尝试和创建时间；补充任务内待处理发现直达及返回条件恢复。使用现有 Ant Design 组件，不重做任务详情信息架构。

### 阶段三：隔离验证与发布边界

实施验收范围如下；规划轮没有执行测试，实施轮的实际结果见第 8 节：

- 已完成但有开放问题、全部已处置但包含忽略、部分覆盖零发现、范围排除 / 豁免、失败 / 取消 / 跳过、关联未知均不出现误导成功结论。
- 全量重审、有效补审、未提升候选、重复发现、多个发现关联同问题、合并链、关闭后重开；发现数和问题数保持各自口径。
- 状态数量不受分页影响，项目 / 问题 / 通知组合筛选、详情邻项及返回 URL 一致，查询失败不伪装成零。
- 初审耗时不冒充补审总耗时，未知历史不填零，排队不增加执行时长；创建时间跨年、时区、缺失值正确。
- 桌面与窄屏、键盘、只读角色、当前页批量冻结、长项目名称、加载失败和缓存刷新。

具体执行命令在实施阶段按测试文件提供，至少包括后端定向测试、前端类型 / lint / 组件测试、隔离构建和实际浏览器检查。只有实际运行且通过才记录通过。

代码完成、本地验证和部署生效分别记录；隔离构建不覆盖 frontend/dist，发布需单独确认范围并核验实际入口，不用文档完成替代页面上线。
