# 聊天自动受理与结构化台账混合记录

## 实际能力与范围

本功能是 [采集方案](chat-problem-capture-proposal.md) 的第一版本地实现，不是全账号抓取，也不保证实时零遗漏。

- 管理员在“问题与改进”顶部展开“聊天自动受理与待核实收件箱”，查看绑定、最近成功时间、失败码、待关联数量和来源分页。
- 只有本机 CLI 显式绑定的当前项目会话可读取。每个绑定必须与启动 monitor 的项目工作目录完全一致；HTTP 只能暂停/恢复已有绑定，不能添加会话或路径。
- 本轮授权边界为当前聊天，从用户选择实施混合方案的消息开始。其他聊天、新建聊天、此前历史不自动纳入。以后增加范围须取得明确授权并显式绑定，不自动发现全账号线程。
- 独立 monitor 每轮完成后等待 30 秒；页面每 5 秒查询。正常约几十秒可见；来源超时、负载、网络或服务停止会延后，不是毫秒级推送或时延承诺。列表中的正式问题沿用原有刷新周期，收件箱可直接进入关联记录。
- 实际验证的是本机 `codex-cli 0.167.0-alpha.3.2` 的 `app-server --stdio`、`thread/read` 元数据与 `thread/turns/list` 摘要分页；没有验证桌面实时消息订阅。官方文档访问返回 403，不以本机实验冒充长期稳定的官方兼容承诺。升级 CLI 后须重新验证。

## 双通路如何协作

1. **聊天通路先保留来源**：适配器只取用户文本与消息标识/时间，核对线程 ID、项目路径和起始时间。只在内存接触返回内容，不存原始转录、工具输出、推理、助手正文、图片或附件内容。
2. **本地规则保守受理**：含“报错、失败、无法、遗漏”等线索的消息自动建立“聊天待核实”记录；其他消息（含继续、咨询、仅附件）保留收件箱，不因规则未命中静默丢弃。无需每条确认，不调用远程提取模型、不产生模型费用。
3. **结构化通路控制结论**：正式记录初始为待处理、代码未修改、验证未运行、部署未知。助手说“通过、完成、上线”不能自动改变这些状态；实际代码、测试、部署事实仍由处理者追加台账和证据，原 monitor 同步和只读收尾核验保留。
4. **去重不等于语义合并**：同绑定、消息 ID、脱敏摘要指纹有唯一约束。相同消息重读零重复；消息编辑追加新来源版本、继承既有关联，不覆盖正式事实、不二次自动建档。不同消息相似或同一句包含多个问题不会擅自语义合并/拆分。
5. **人工更正可逆**：可关联已有记录、解除关联、把未关联候选建为待核实记录。操作要求当前版本，冲突返回 409、保留输入，关联追加审计，不改目标问题结论。自动建档与手写台账可能描述同一事项；可更正关联并人工处置重复正式记录，本版不自动删档或去重历史事实。

## 中断、撤权与有界补偿

每轮在授权起点以内按新到旧分页重读，用 SQLite 唯一键去重；**不是已实现增量游标或全历史后台回填**。`last_message_ms` 是最后成功摄取的观测值，不是证明所有语义均已识别的水位。重启后仍重读授权范围，可补偿提交前中断及来源编辑。

- 一轮最多 100 页，每页 25 回合；初始化、元数据及分页合计约 20 秒读取截止，单响应最多 5 MiB。超时、协议变更、重复游标、元数据不符或分页超过上限均报错，不把半轮写成成功，不静默缩短历史范围。达到上限需维护者规划分段补偿，当前没有一键分段历史回填。
- 完整读取后才开启短写事务；来源、自动记录和版本一起提交，异常全部回滚。下轮重试，不发送业务评审请求。
- 暂停使绑定版本变化；在途读取提交前再次核对授权，撤权后不再入库。恢复后仍在原起点补读；重复绑定不重启被暂停授权，也不扩大范围。
- 页面区分未绑定、未启动/过期、采集失败、近期正常、已暂停。超过 120 秒未成功或 `source_unavailable` 不称为健康；请求失败不显示零问题。`source_unavailable` 只表示来源不可用或无法验证，应检查 CLI、登录、项目工作目录及协议；不保存原始外部错误正文。
- 沿用原 monitor 的 30 秒周期，不增加新的定时任务，不占付费评审 Worker。采集超时会顺延 monitor 本轮后续工作；没有独立推送、每条即时告警或自动重启服务承诺。

## 隐私与仍可能遗漏的边界

脱敏规则删除代码块、引用、已知凭据模式、URL、常见绝对路径、私钥和长标识，最多保留 800 字摘要；不能证明识别任意自定义秘密，聊天中仍不应粘贴凭据。来源内容仅作数据，绝不执行其中的终端指令或附件提示。

本版没有附件 OCR、复杂多问题拆分、跨消息语义关联、自动清除/保留期限管理，也没有恢复来源已删除消息的能力；长消息摘要会截断，需回原聊天核对。只有脱敏文本变化才产生新版本，仅变化的被省略内容不会产生可见新版本。图片里的问题、含糊表达、未授权会话、服务停机期间来源被删、接口升级和超出扫描上限均可能遗漏。保留全部已读消息的有界线索、健康提示和结构化受理是降低风险，不是百分之百识别保证。

数据库仍是事实来源；聊天来源表与正式记录不提供 HTTP 物理删除接口，暂停不删除已留痕历史。历史清理需独立备份、授权和设计，不手工删表破坏关联。页面和正式改进记录都只允许管理员访问。现有公网 HTTP 域名没有传输加密，本功能没有改变这一风险；管理使用本机回环地址或受控 HTTPS，不能把文本脱敏当成传输加密。

## 本机运维

从项目根目录启动，沿用当前实例私有配置，先成对备份并迁移到 schema 47。绑定命令要求数据库已存在、版本匹配，不隐式创建空库或自动迁移：

```sh
cd /Users/seakoi/Desktop/openCodeReview
export PYTHONPATH="$PWD/backend"
export OCR_APP_CONFIG_FILE="$PWD/.local-data/local/private.json"
# 仅在获得对应线程和起点范围授权后执行，起点为毫秒时间戳。
.venv/bin/python -m ocr_manager.chat_capture \
  --bind-thread '<已授权线程 ID>' \
  --project-root "$PWD" --since-ms '<已授权起始毫秒>' --scan-once
```

命令输出仅绑定及摄取计数；适配器优先使用 `CODEX_APP_SERVER_COMMAND` 指定的可执行文件，否则查找 `codex`，macOS 再使用已验证的应用内 CLI 路径。该变量只能由本机受信任运维设置，HTTP 不可修改；不要指向未知程序。日常仍由既有 `python -m ocr_manager.alerts` 循环自动采集，不必重复手动扫描。新建聊天需重新授权绑定，旧会话绑定不会自动跟随新聊天。

## 可执行验证

以下仅使用合成协议、临时 SQLite 和隔离浏览器服务，不调用付费模型：

```sh
.venv/bin/pytest -q backend/tests/test_chat_capture.py backend/tests/test_chat_capture_protocol.py
.venv/bin/ruff check backend/ocr_manager backend/tests
.venv/bin/mypy backend/ocr_manager
PYTHONPATH=backend .venv/bin/python -m ocr_manager.openapi_contract
npm --prefix frontend run lint
npm --prefix frontend test
cd frontend
npx tsc -b
npx vite build --outDir /tmp/ocr-chat-capture-dist --emptyOutDir
OCR_BROWSER_CHAT_CAPTURE=1 OCR_BROWSER_FRONTEND_DIST=/tmp/ocr-chat-capture-dist \
  npx playwright test e2e/chatCapture.spec.ts
```

无自带 Playwright 浏览器时可显式设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 为本机 Chrome。业务库发布必须单独进行空闲检查、成对备份、恢复演练和只读核验，测试通过不等于部署生效。
