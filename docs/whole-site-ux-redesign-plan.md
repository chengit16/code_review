# 全站页面体验排查与重设计规划

> 2026-11-07；关联 PI-20261107-011。运行监控四分区方案已获用户确认，详见 [运行监控页重设计规划](operations-redesign-plan.md)。本文是实施规划，不表示页面已修改或已部署。

## 检查方式与范围

根据本次运行监控截图、当前工作区路由和主要 React 页面源码作静态排查；没有对全部页面进行真实数据、所有角色及各屏宽的逐页视觉验收。以下判断分为“源码确认”和“体验风险待验证”，不是已经测量的用户行为或性能结论。实施前针对高优先级页面补隔离浏览器基线。

已核对现有管理员和只读角色可达的主要页面：运行概览、评审任务与任务详情、待跟进问题、合并前审查、合并事件、运行监控、问题与改进及其两类详情、项目配置、系统设置（三个标签）、首次接入、配置历史和访问权限。旧路由跳转至上述页面，不另做重复改造。

## 总体设计方向

- 沿用现有灰白蓝主题、字体和图标；用户后续已授权 Ant Design，新增/重设计通用控件按统一规则使用，存量分批迁移，不作全站换肤或一次性全量替换。
- 将页面分为“列表工作台”“单项详情”“配置编辑”“低频维护”四种模板；不把所有页面都强行改成标签页。
- 先回答当前状态与下一步，再展开历史、证据和高级参数。可能产生费用、外部发布或删除的操作保持清晰后果与确认。
- 时间范围、状态口径、未知值、样本量和数据来源写在相应数字附近。查询失败不是零，历史异常不是当前故障，人工标记修复不等于系统验证修复。
- 常用筛选和操作露出；低频高级条件折叠但可发现。筛选、视图、详情和分页的既有 URL 行为原则上保留并兼容旧链接。
- 窄屏优先保证任务标识、状态、关键结论和操作；其余信息可展开，不能因折叠丢失业务事实。键盘、焦点、语义标签和非颜色状态同步验证。

## 按页面检查结果及建议

### P0：影响判断、权限或操作安全，先复现确认并修正

#### 首次接入引导 `/onboarding`

- 源码确认：进度在请求加载或失败时仍按缺省空数据计算；`webhookReady` 仅检查已启用项目有回调 URL，并不能证明 GitLab 已配置或成功投递。检查结果使用 `some(status === passed)`，还需要核对后端返回是否保证最新、按当前配置关联；不能仅凭任意历史通过判定当前连接正常。
- 改进：加载/失败时显示“读取中/无法确认”，不显示确定进度；区分“地址已生成”和“GitLab 配置已验证”。验证项需按受支持的最新记录及配置范围呈现；若 API 不足则先定义并测试只读契约，避免前端猜测。保留去各设置页的路径。

#### 账号与关联配置的未知状态

- 源码确认：`UsersPage` 在认证模式读取失败时以 `false` 作为复选框值；`RepositoriesPage` 对接入状态缺失使用“待重新测试”、关联飞书名称缺失显示“未配置”；`FeishuHooksPage` 的关联仓库数据缺失可显示“尚未关联仓库”。这些查询各自有不同失败处理，不应把未获取到的数据都当成确定事实。
- 改进：分别渲染加载、不可用、未配置；敏感开关只在读取成功后允许操作，主查询及辅助查询各自提供重试。缓存过期但仍展示旧数据时标明读取失败或数据可能过期，不自动重放写请求。

### P1：高频业务工作流

#### 运行监控 `/operations`

- 用户已确认：单菜单下分为“运行与并发、性能分析、告警与通知、维护与审计”；默认展示运行状态、关注事项、执行槽和 1～10 并发控制。
- 不改变现有调度和自动重试规则。已保存与已应用并存，调低排空、心跳过期和版本冲突必须有独立状态。原完整设计与验收见 `operations-redesign-plan.md`。

#### 评审任务列表 `/jobs`

- 源码确认：列表桌面有任务、仓库、提交、提交人、结论、通知、耗时、费用、创建时间等列；已有快捷筛选、高级筛选、URL 定位和窄屏摘要，不能简单认定没有移动适配。
- 体验风险：高密度行同时包含多个时间和结论，横向比较成本可能偏高；多选批量操作与常用查询相邻，需在真实屏宽验证。
- 改进：保留现有快捷/高级筛选、分页和已生效标签；核心列表突出任务来源、结论/覆盖、耗时、通知和行动，次要提交与费用按需展开。明确多选作用于本页可重审任务，保留逐项失败反馈、锁定和原筛选返回。

#### 评审任务详情 `/jobs/:id`

- 源码确认：状态摘要后依次堆放耗时、失败分析、覆盖原因、补审、有效结论或发现、模型用量、覆盖、行内发布、文件、历史、通知和尝试时间线；部分历史已经折叠。核心发现和补审可能被排障内容挤到下方。
- 改进：标题区呈现任务来源、当前有效结论和覆盖摘要；按“结果与发现 / 失败与补审 / 执行与费用 / 通知与历史”组织，可用 URL 标签或页内锚点，具体依隔离基线选择。失败、部分覆盖和有效结论的证据保持可达；补审冻结范围/预算、人工批准和旧结论不简化。重发通知与重新评审保持独立，标明费用与后果。

#### 待跟进问题 `/issues`

- 源码确认：筛选、搜索、批量栏及九列以上表格同屏；详情已有 URL 定位、桌面侧栏/窄屏全屏、历史按需展开，具备可复用基础。
- 改进：列表突出问题摘要、项目、级别、状态和最近出现；次要提交人与完整路径在详情或展开区保留。批量栏仅在选择后强调，不能减少“全选本页”范围提示；详情先呈现问题与处理状态，再显示出现记录和处理历史。明确提交人不是责任人，人工修复不是自动验证。

#### 合并前审查 `/premerge`

- 源码确认：点击详情后在列表上方插入完整详情；大量发现或证据可能让原列表位置下移。已有历史版本开关、URL 详情和有效性警告。
- 改进：优先评估可关闭侧栏/独立详情视图，使筛选与列表位置保持；默认突出最新版本、覆盖状态和发现。旧版本、取消、失败、纯换行排除不能暗示通过；保留原 URL 或兼容跳转。

#### 合并事件 `/events`

- 源码确认：管理员的补审申请表与申请历史放在事件收件箱之前，且两个功能语义不同；扫描完成不等于评审完成。
- 改进：默认先显示事件收件箱与异常筛选；“历史 MR 补扫”成为明确独立的次级入口及历史区，仍保留 31 天限制与确认。事件恢复只重新核验 GitLab，不冒称评审完成。

### P2：配置与平台管理

#### 项目配置 `/repositories`

- 源码确认：列表同排展示项目、分支、接入、Webhook Secret、接收开关和操作；编辑弹窗已有“基础接入、评审参数、发布审查、接入诊断”分区，多个设置分别保存，行内发布开关自动保存。
- 改进：列表优先展示项目和接入状态，Secret 保留按需查看/复制，不新增长期明文缓存；编辑视图突出当前保存范围及各分区未保存状态，不能把自动保存误称需统一提交。删除与轮换继续清楚说明对历史和 GitLab 的影响。`useConfigurationDraft`、离开保护和诊断分区已有机制应复用。

#### 系统设置 `/settings`

- 源码确认：模型、飞书、审核规则已经有 URL 标签；不建议重复新建分类导航。模型和飞书列表分别有编辑弹窗；审核规则同时展示编辑、反馈、预览和版本历史，项目规则较多时可能变长。
- 改进：保留现有标签及草稿保护；审核规则围绕“范围与规则、预览、版本历史”分区，关键优先级和生效范围常显。模型列表区分已保存、已启用、测试针对谁；飞书列表区分通道与关联项目。API key、Webhook 与 Token 不回显，测试可能产生成本或外部消息的提示不能移除。

#### 问题与改进 `/improvements` 及详情

- 源码确认：列表已有“问题记录、优化历程、复盘汇总”视图和 URL；自动归档与聊天收件箱已经折叠，但每次进入都在视图标签之前，且各自发起轮询。主题详情逐阶段完整展示目标、办法、三个维度和证据，阶段增多时变长。
- 改进：保留三个已有主视图，将归档/聊天工具移至可发现的次级入口，并提供真实的同步/采集异常提示；主题详情以阶段摘要定位，展开看完整证据。无论如何保留“代码修改 / 本地验证 / 部署生效”三个独立维度、历史版本、归档事实和隐私边界，不能隐藏或自动宣称完成。

#### 配置历史 `/config-history`、访问权限 `/users`

- 源码确认：配置历史支持按对象筛选和展开变更，恢复由单一图标触发确认；账号设置和认证模式放在同一页。数据规模与窄屏阅读风险需实测。
- 改进：配置历史展示清楚对象、变更数量、是否可恢复与不可恢复原因；恢复显式说明密钥和当前启用状态边界。账号页突出认证模式、启用前提和受影响会话，危险删除保留二次确认。只读用户不可见的管理路由和服务端鉴权不变。

#### 首页 `/`

- 源码确认：已有 Worker 状态、待办中心、有效结论与历史失败区分；评审效果统计和趋势出现在最近评审之前，统计占用随视图而变。
- 改进：保留“当前待办优先”的已有方向，评估将最近评审提前、效果趋势改为次级视图或精简摘要；不复制运行监控全部功能。已标记修复仍表述为人工结论。

## 统一交互规范

1. **状态**：运行、排队、完成、部分、失败、跳过、取消与过期保持不同措辞；失败请求、加载和空结果分开。数字对应的时间、范围与口径在近处可见。
2. **导航**：原路由、筛选、详情、浏览器前进后退尽量兼容；需要迁移时提供旧 URL 映射和回归测试。标签有键盘操作、焦点与明确选中态。
3. **查询**：局部刷新只刷新明确范围；显示最近成功读取而不是伪造服务端更新时间；可按需加载重型分区，但不能因卸载丢失草稿。
4. **写操作**：重新评审、通知重发、补审、发布、恢复、清理各有独立语义；确认框说明对象和后果，保留 409 草稿和逐项失败，服务端负责权限与最终校验。
5. **响应式**：桌面 1440/1024、平板 768、手机 375/320px；允许必要的局部横向表格滚动，不允许页面整体溢出或靠 hover 才能操作。
6. **维护性**：按职责拆分 React 子组件与查询层，复用业务封装、草稿守卫及主题变量；通用控件统一 Ant Design，具体迁移边界见[前端规范](governance/frontend-code-standards.md#8-ant-design-采用规则)。存量组件在无调用前不移除。

## 分批实施与验收

### 第一批：确定事实与运行监控

先对 P0 涉及的读取失败/进度语义做隔离复现并修正；随后实施已确认的运行监控四分区。复核用户截图与当前源码版本差异，保留既有全部能力。

验收：加载/失败不能伪装成未配置或完成；四分区可从 URL 定位；并发上限 1～10、默认/已应用/排空/冲突/十槽、服务停止和异常均真实呈现；旧入口可达。

### 第二批：评审主链路

按任务列表 → 任务详情 → 待跟进问题 → 合并前审查 → 合并事件调整，优先保留筛选和上下文，再做细节密度优化。补审、重评、通知、权限和覆盖结论均须回归。

验收：从待办进入任务，能保持筛选返回；失败/部分/跳过不显示通过；读者只能查看；预审旧版本明确失效；每种重试只触发原有对应操作。

### 第三批：配置、平台管理与首页

调整项目配置、系统设置、问题与改进、配置历史、账号页和首页。对首次接入安全语义优先按第一批修正，其他视觉/交互再在本批统一完成。

验收：密钥不回显，弹窗和路由离开保护有效，关联/归档/历史证据不丢，角色授权不倒退；各查询失败、已保存/未保存/自动保存均有正确提示。

### 第四批：全链路回归和发布准备

汇总并逐页比较基线截图；覆盖宽屏/窄屏、键盘、主要页面空/加载/错误/极长数据、回退、并发版本冲突、补审预算和风险操作。通过后同步项目总览、操作指南与交互回归文档；先构建临时产物，再由用户确认本机切换。

## 非目标与交付状态

本轮不重新设计业务流程或自动化策略，不引入额外 Worker，不增加新图表/筛选所需的未定义数据，不改密钥模型，不自动发送外部通知或评审。以上排序可按用户优先级调整；规划已整理，所有页面重排、测试和本机部署尚未实施。
